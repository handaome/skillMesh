## 1. 项目背景与目标

AI 编程 Agent 已经可以通过 Skill 目录加载任务说明、参考资料、脚本和模板，但 Skill 的发现、跨设备同步、第三方来源管理、团队共享及更新策略通常分散在不同工具和目录中。SkillMesh 在不改变开发者原有使用习惯的前提下，为这些 Skill 提供统一的管理平面。

### 1.1 产品目标

- 本地 Skill 自动发现与可配置的无感备份：监听授权目录、增量同步、断网续传。
- 支持 GitHub、GitLab、Gitee 和自建 Git 服务中的 Skill 导入、安装、更新、固定版本与回滚。
- 支持个人私有空间、团队共享空间和经过审核的组织级 Skill 市场。
- 通过适配器安装到 Claude Code、Codex、Cursor 等 Agent 的原生 Skill 目录。
- 提供统一版本、来源、摘要、权限、审计和安全扫描记录。
- 为后续 MCP 工具服务和企业工作流集成预留扩展点。

### 1.2 非目标（首期不做）

- 不替代 Agent 本身的推理、上下文管理或原生 Skill 发现机制。
- 不在服务端执行 Skill 内的脚本；默认在用户自己的开发环境中执行。
- 不承诺静态扫描能证明 Skill 绝对安全。
- 不将所有第三方仓库自动镜像或公开到团队市场。
- 不把 MCP 工具运行时与 Skill 制品注册中心耦合为同一个模块。

## 2. 核心概念与产品规则

| 概念 | 定义 | 关键规则 |
| --- | --- | --- |
| Skill | 包含 SKILL.md 及可选 references/scripts/assets 等文件的目录。 | 优先兼容主流 Agent Skills 格式；扩展元数据独立保存。 |
| 来源 Source | 本地目录、Git 仓库、SkillMesh 远程注册中心。 | 每个安装实例必须记录来源类型和定位信息。 |
| 安装实例 | 某个 Skill 被安装到某个 Agent、用户或项目的记录。 | 安装状态与云端版本记录分离。 |
| 个人云端备份 | 用户授权同步到自己空间的 Skill 内容。 | 默认私有，不等于团队发布。 |
| 团队发布 | 将 Skill 作为组织可用资产发布。 | 遵循团队权限、扫描与审核流程。 |
| 不可变版本 | 发布后内容固定、摘要固定的版本制品。 | 禁止静默覆盖已发布版本；修复通过新版本完成。 |
| 同步基线 | 用于比较本地和云端变更的共同版本/文件摘要。 | 双方都变更时必须执行冲突处理，不允许盲目覆盖。 |

### 2.1 四条独立链路

| 链路 | 触发 | 结果 |
| --- | --- | --- |
| 本地 → 个人云端 | 本地文件变更、用户授权同步 | 私有备份或个人草稿更新 |
| Git → 本地 Agent | 用户安装或检查更新 | 按目标 Agent 目录安装指定提交/版本 |
| 云端 → 本地 Agent | 安装团队 Skill 或拉取云端更新 | 安装已授权版本，记录锁文件与摘要 |
| 个人/团队 → 团队市场 | 用户主动发布或提交审核 | 经过扫描和权限审核后可供团队发现 |

## 3. 用户场景与流程

### 3.1 本地 Skill 无感同步

1. 用户登录 SkillMesh 并选择需要管理的 Agent 与目录。
1. 本地 Daemon 扫描 Skill 目录，识别包含有效 SKILL.md 的候选目录。
1. 首次发现时按策略询问、跳过或加入个人私有备份；不得默认公开。
1. 对文件变更进行防抖、哈希比对、敏感信息检查，再上传差异。
1. 网络失败时写入本地任务队列，恢复后重试；同步任务幂等。
1. 其他设备登录后可恢复个人 Skill；双向变更时按基线比较并解决冲突。

### 3.2 从 Git 安装第三方 Skill

1. 用户提供仓库 URL，可选指定子目录、分支、标签或 commit。
1. 服务端或 CLI 解析仓库来源，定位一个或多个 Skill 目录并展示清单。
1. 用户选择 Skill、目标 Agent、用户级/项目级安装范围和更新策略。
1. 客户端在临时目录获取内容，校验路径、文件清单、大小限制及安全策略。
1. 通过适配器安装到目标目录，写入来源记录与已安装 commit/hash。
1. 安装完成后展示来源、许可证（若可识别）、版本和风险提示。

### 3.3 更新与回滚

1. 检查远程 ref 指向的最新 commit 或注册中心最新可用版本。
1. 下载到临时目录并与当前版本进行文件级差异比较。
1. 如果本地无修改，按策略提示或自动更新；如果本地有修改，保留本地版本并提示冲突。
1. 更新成功后原子切换安装目录，并保留前一版本或可重建的制品以支持回滚。
1. 固定 commit/tag 的来源不自动漂移；只有用户明确升级才变更版本。

## 5. 总体技术架构

采用“中心化管理、客户端拉取、本地缓存、本地执行”的架构。云端管理元数据、权限、版本和制品；本地 Daemon/CLI 负责发现、同步、校验与安装；Agent 继续使用原生目录加载 Skill。

| 层级 | 组件 | 职责 |
| --- | --- | --- |
| 客户端 | skillmesh CLI | 登录、搜索、安装、更新、发布、回滚、诊断。 |
| 客户端 | skillmesh watch | 文件监听、同步队列、目录扫描、冲突检测、后台更新检查。 |
| 客户端 | Agent Adapter | 管理各 Agent 的目录、安装规则、冲突与发现兼容性。 |
| API 层 | REST API / Auth | 身份认证、授权、限流、元数据与制品访问入口。 |
| 业务层 | Registry Service | Skill、来源、版本、组织、权限、审核状态。 |
| 业务层 | Artifact Service | 制品上传下载、哈希校验、不可变存储与签名信息。 |
| 业务层 | Scan/Audit Service | 安全扫描、审核工作流、审计事件。 |
| 存储层 | PostgreSQL | 结构化元数据和关系。 |
| 存储层 | S3/MinIO | 版本制品、归档包、扫描报告等对象。 |
| 外部系统 | Git 服务 / OIDC / MCP | Git 源获取、企业登录；MCP 为后续独立扩展。 |

### 5.1 推荐技术栈

| 部分 | 建议选型 | 原因 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript | 适合管理后台与市场 UI。 |
| 后端 | Spring Boot 3 / Java | 便于企业权限、审计和业务集成。 |
| CLI/Daemon | Go | 跨平台单文件分发，便于常驻后台进程。 |
| 数据库 | PostgreSQL | 事务、索引与结构化元数据。 |
| 制品存储 | MinIO 或兼容 S3 对象存储 | 大文件与版本制品独立存储。 |
| 源码协作 | GitHub/GitLab/Gitee/自建 Git | 保持作者原始协作流程。 |
| 认证 | OIDC；企业环境可接 LDAP/SSO | 统一身份与令牌生命周期。 |
| 部署 | Docker Compose 起步，后续可迁移 Kubernetes | 首期降低运维复杂度。 |

## 6. 本地同步引擎设计

### 6.1 发现与目录规则

- 允许用户选择并授权需要扫描的目录，不应默认扫描整个磁盘。
- 支持用户级目录、项目级目录和自定义目录；Agent 路径应通过适配器配置管理，
  额外目录通过 `sync.extra_dirs` 配置。
- 仅将符合 Skill 结构的目录列为候选，支持 .skillmeshignore 排除规则。
- 默认忽略 .git、缓存、临时文件、系统文件、凭据文件和超出大小限制的文件。
- 不跟随目录外部的符号链接，避免上传授权目录之外的数据。

### 6.2 文件变更处理

- 文件系统事件仅用于触发扫描；通过短暂静默期合并连续写入，避免上传半成品。
- 计算相对路径与 SHA-256；未变化文件不重复传输。
- 上传前进行敏感信息扫描；可疑内容默认阻止上传或要求用户明确确认。
- 使用幂等任务 ID、重试队列和指数退避，保证网络中断后可恢复。
- 云端提交使用版本/ETag 条件更新，避免两个设备同时写入造成静默丢失。

### 6.3 冲突策略

| 本地状态 | 云端状态 | 处理方式 |
| --- | --- | --- |
| 未变更 | 已变更 | 按云端拉取策略更新本地。 |
| 已变更 | 未变更 | 上传本地变更，前提是通过过滤和安全检查。 |
| 已变更 | 已变更且不同文件 | 可按文件合并，记录新的共同基线。 |
| 同一文件双方变更 | 冲突 | 尝试文本三方合并；无法安全合并则生成冲突副本并暂停自动覆盖。 |
| 本地删除 | 云端仍存在 | 先进入删除待确认/回收流程；不得因为一次目录扫描异常直接删除云端内容。 |

### 6.4 同步设置默认值

| 设置 | 默认值建议 |
| --- | --- |
| 新发现 Skill | 首次询问或同步到个人私有空间；绝不默认公开。 |
| 已授权目录变更 | 自动增量备份。 |
| 云端更新 | 自动检查，冲突时暂停覆盖。 |
| 团队发布 | 手动提交，经过策略/审核后发布。 |
| 删除传播 | 软删除、回收期、支持恢复。 |
| 离线模式 | 保留本地文件与队列，不影响 Agent 使用。 |

## 7. Git 来源管理与更新

### 7.1 来源模型

| 字段 | 含义 |
| --- | --- |
| provider | github、gitlab、gitee、generic_git 等来源类型。 |
| repository_url | 规范化仓库 URL；凭据不得写入 URL。 |
| subpath | 仓库内 Skill 子目录，可为空。 |
| ref_type | branch、tag、commit。 |
| ref_value | 用户配置的分支、标签或固定 commit。 |
| resolved_commit | 安装时实际解析到的 commit SHA。 |
| installed_hash | 安装内容的规范化摘要。 |
| license | 识别到的许可证信息及识别状态，不可假定一定可分发。 |
| update_policy | manual、notify、auto_safe。 |

### 7.2 更新策略

| 策略 | 行为 | 适用情况 |
| --- | --- | --- |
| manual | 不自动检查或应用，用户主动操作 | 关键生产 Skill、固定依赖 |
| notify | 后台检查并提示差异，用户确认应用 | 默认推荐，尤其是第三方来源 |
| auto_safe | 通过安全策略、无本地冲突且满足版本规则后自动更新 | 经过信任审核的低风险 Skill |

### 7.3 Git 安装安全

- 校验 URL 协议与主机，默认仅允许 HTTPS/SSH；拒绝 file://、危险本地路径和可疑重定向。
- 防止路径穿越、归档炸弹、超大文件、恶意符号链接及目标目录逃逸。
- 私有仓库凭据使用系统凭据管理器或受控令牌，不写入 Skill、日志或遥测。
- 显示来源仓库、作者信息（若可得）、commit、许可证检测结果和风险提示。
- 不因 Git 来源可信就跳过 Skill 内容扫描；安装与执行权限仍由用户环境决定。
- 对第三方内容的云端复制或团队再分发进行许可证与组织策略检查。

### 7.4 推荐 CLI 命令

```bash
skillmesh login https://skills.example.com/api/v1   # 位置参数是服务端地址；OIDC issuer 从它的公开配置里取
skillmesh search java-debug
skillmesh add https://github.com/owner/agent-skills --path skills/java-debug --agent claude-code --scope project
skillmesh add https://git.example.com/team/skills.git --path skills/release --ref v1.2.0
skillmesh list
skillmesh update --check
skillmesh update java-debug --dry-run
skillmesh update --all
skillmesh sync
skillmesh publish ./skills/java-debug
skillmesh rollback java-debug --to 1.1.0
skillmesh uninstall java-debug
```

## 8. 多 Agent 适配器

适配器只负责 Agent 的目录与发现规则，不负责维护另一份 Skill 内容。安装时保留标准 Skill 目录结构，必要时做兼容性检查。Agent 的目录约定可能随版本变化，因此路径应配置化并有测试。

| Agent | 常见用户级位置 | 常见项目级位置 | 注意事项 |
| --- | --- | --- | --- |
| Claude Code | ~/.claude/skills/ | .claude/skills/ | 检查同名 Skill 与项目级覆盖行为。 |
| Codex | ~/.codex/skills/ 或 CODEX_HOME 下的 skills/ | .agents/skills/ | 支持自定义 CODEX_HOME；发现规则需版本测试。 |
| Cursor | ~/.cursor/skills/ 或 ~/.agents/skills/ | .cursor/skills/ 或 .agents/skills/ | 按当前 Cursor 版本验证支持路径。 |
| 其他 Agent | 适配器配置定义 | 适配器配置定义 | 若格式不兼容，提示能力差异，不静默改写源内容。 |

路径为设计基线，实施时应以目标 Agent 当前官方文档和实际版本测试为准。用户级安装适合个人跨项目复用；项目级安装适合团队锁定版本并纳入项目版本控制。

## 9. 版本、锁文件与制品

### 9.1 版本原则

- 草稿可变，已发布版本不可变。
- 同一 Skill 的版本号在同一注册中心内唯一；每个制品都保存 SHA-256。
- 项目锁文件记录 Skill ID、来源、版本/commit、制品摘要和目标路径。
- 更新先下载到临时目录，完成校验后再原子切换安装目录。
- 保留上一版本或可重建制品，支持回滚；回滚也必须写审计日志。

### 9.2 锁文件示例

```yaml
version: 1
resolved_at: 2026-10-19T08:00:00Z
skills:
  - name: java-service-debug
    repository: https://github.com/example/agent-skills.git
    provider: github
    path: skills/java-debug
    ref_type: tag
    ref: v1.2.0
    resolved_commit: <resolved-commit-sha>
    installed_hash: <本机内容的摘要>
    scope: project
    update_policy: notify
    agents: [claude-code]
    target_path: <实际装到的路径>
    license: MIT
```

注册中心来源的条目用 `source_id` / `version` / `sha256` 代替来源与 commit 那几项。

## 10. 权限与安全治理

| 控制项 | 要求 |
| --- | --- |
| 认证 | 个人访问使用 OIDC 或安全登录流程；CLI 令牌可撤销、过期并支持刷新。 |
| 授权 | 至少区分组织管理员、团队管理员、发布者、审核者、使用者。 |
| 默认隐私 | 本地同步到个人私有空间；公开/团队共享需要单独授权或审批。 |
| 密钥防护 | 上传前检测常见凭据；禁止在 Skill 包中存储真实密钥；检测命中可阻断。 |
| 内容扫描 | 扫描脚本、可疑命令、外部下载、路径穿越、隐藏文件和依赖信息。 |
| 制品完整性 | 记录 SHA-256；可对发布清单签名并在客户端验证。 |
| 执行边界 | Skill 默认在本地 Agent 环境执行；不在注册中心服务端运行不可信脚本。 |
| 审计 | 记录发布、审批、下载、安装、升级、撤回、权限变更和策略变更。 |
| 撤回 | 撤回改变可用状态并保留记录；客户端下次同步时提示风险，不无痕删除本地内容。 |

### 10.1 发布状态机

draft → scanning → pending_review → published。

`scanning` 是给异步扫描预留的：当前扫描在转正的同一个事务里同步做完，
没有可观察的中间态——版本要么停在 `draft`，要么已经是终态。

两个终态要分得清：

| 终态 | 什么时候 | 含义 |
| --- | --- | --- |
| `quarantined` | 服务端扫描命中阻断规则（内容里有真凭据之类） | 隔离。没进审核队列，也不能重新送审——送审那道闸看的是扫描结论，绕不过去 |
| `rejected` | 审核者驳回 | 驳回后可以改好了重新送审 |
| `revoked` | 紧急事件撤回已发布的版本 | 不可逆。既有安装需要收到撤回提示并按组织策略处理 |

### 10.2 风险边界

静态扫描和签名只能帮助验证来源与发现风险，不能证明 Skill 无恶意行为。高权限 Skill 应要求人工审核、最小权限和隔离测试；Agent 的工具权限仍由 Agent 本身及运行环境控制。

## 11. 数据模型

| 实体 | 核心字段 | 说明 |
| --- | --- | --- |
| users | id, subject, display_name, status | 用户身份映射。 |
| organizations | id, name, policy_json | 组织与全局策略。 |
| teams | id, organization_id, name | 团队工作空间。 |
| memberships | user_id, team_id, role | 团队成员与角色。 |
| skills | id, owner_id, visibility, name, description | Skill 逻辑实体。 |
| skill_sources | id, skill_id, source_type, url, path, ref | Git/本地导入/云端来源元数据。 |
| skill_versions | id, skill_id, version, commit_sha, sha256, artifact_key, status | 不可变版本与制品指针。 |
| skill_scans | version_id, scanner_version, findings_json, status | 扫描报告与状态。 |
| installations | user_id, device_id, skill_id, agent, scope, version, path | 本地安装实例。 |
| sync_states | device_id, skill_id, base_revision, local_hash, cloud_revision | 双向同步基线与状态。 |
| audit_events | actor_id, action, target, result, timestamp, metadata | 安全审计事件。 |

建议为 skill_id + version 建立唯一约束；制品存储键不可复用覆盖。权限判断应同时校验组织/团队可见性和具体操作权限。同步状态应与发布版本分开建模。

## 12. API 设计

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/v1/skills?q=&source=&visibility= | 搜索和筛选 Skill。 |
| POST /api/v1/skills | 创建 Skill 元数据。 |
| GET /api/v1/skills/{id} | 获取 Skill 详情。 |
| GET /api/v1/skills/{id}/versions | 查询版本列表。 |
| POST /api/v1/skills/{id}/versions | 上传/创建候选版本。 |
| POST /api/v1/skills/{id}/versions/{v}/submit | 提交审核。 |
| POST /api/v1/skills/{id}/versions/{v}/approve | 审核通过并发布。 |
| GET /api/v1/skills/{id}/versions/{v}/artifact | 经过授权后获取制品。 |
| POST /api/v1/sync/changesets | 提交同步变更集。 |
| GET /api/v1/sync/changesets/{id} | 查询同步结果。 |
| POST /api/v1/sources/resolve | 解析 Git 来源与候选 Skill。 |
| POST /api/v1/sources/check-updates | 检查指定来源的更新。 |
| POST /api/v1/audit/events | 写入允许客户端上报的审计事件。 |

所有写接口应具备身份认证、权限检查、请求大小限制和幂等设计。制品下载应先授权，再使用受控下载地址或认证文件流；不应返回含长期权限的公开 URL。

## 13. 错误处理与可观测性

| 情况 | 系统行为 |
| --- | --- |
| 网络断开 | 保留本地工作与同步队列，恢复后重试。 |
| 令牌过期 | 暂停云端操作，提示重新认证；不得丢弃本地修改。 |
| 权限被撤销 | 停止后续下载/上传并记录审计；不自动删除用户本地数据。 |
| 远程版本冲突 | 不覆盖，保存冲突副本并提供差异。 |
| 安全扫描命中 | 阻止自动上传/更新，展示命中规则与处理建议。 |
| 磁盘空间不足 | 取消临时安装并保留当前可用版本。 |
| Agent 目录被占用或不存在 | 提示适配器诊断结果，不声称安装成功。 |
| Git 远端不可用 | 保留已安装版本，提示最后检查时间与来源状态。 |

日志应包含请求 ID、Skill ID、版本、来源类型、动作、结果和耗时；不得记录访问令牌、私钥、完整敏感文件内容。客户端提供 skillmesh doctor 用于诊断配置、目录权限、认证状态和同步队列。

## 14. 部署与运维

首期建议采用 Docker Compose 部署 API、Web、PostgreSQL、对象存储与反向代理。企业内部环境可接入已有 OIDC/LDAP，制品存储可使用 MinIO 或现有兼容 S3 的服务。生产部署需要定期备份数据库与对象存储，并验证恢复流程。
- 服务端使用 HTTPS；内部网络也不应依赖明文传输敏感凭据。
- 数据库保存元数据，对象存储保存不可变制品；备份策略分别制定。
- 设置制品大小、文件数、扫描时间和 API 请求频率限制。
- 为 Git 下载任务设置超时、并发上限与允许的主机策略，避免 SSRF 与资源耗尽。
- 支持版本化 API 与客户端兼容策略，Agent 目录规则可独立更新。

## 15. 实施计划与验收标准

| 阶段 | 交付内容 | 验收标准 |
| --- | --- | --- |
| MVP 1：基础仓库 | 认证、Skill 元数据、制品上传下载、搜索详情、版本不可变 | 用户可创建/查看 Skill，制品摘要校验通过，权限隔离有效。 |
| MVP 2：CLI 与 Agent | CLI 登录、Git 安装、目录适配、安装清单、检查更新 | 从 Git 指定子目录安装；能显示来源、commit 和目标路径；失败不破坏旧版本。 |
| MVP 3：本地同步 | Daemon 目录监听、增量同步、离线队列、私有空间 | 本地修改可在网络恢复后同步；重复事件幂等；敏感文件按规则阻断。 |
| 阶段 2：团队治理 | 团队空间、审核流程、扫描、审计、撤回、回滚 | 未授权用户无法下载私有 Skill；发布过程可追踪；旧版本可恢复。 |
| 阶段 3：扩展生态 | 更多 Agent 适配器、自动更新策略、MCP 集成预留 | 新增 Agent 不需要修改注册中心核心数据模型。 |

### 15.1 关键验收用例

- 在 Claude Code 目录中新建 Skill，Daemon 按策略发现并同步到个人私有空间。
- 在 Git 仓库中指定 Skill 子目录安装，记录实际 commit 与摘要。
- 上游更新后可检查差异；本地有未提交修改时不得直接覆盖。
- 两个设备同时修改同一文件时进入冲突处理，不丢失任一侧内容。
- 包含已识别密钥的 Skill 上传被阻断并给出原因。
- 无团队权限的用户无法下载团队私有 Skill。
- 已发布版本内容不可被相同版本号覆盖。
- 更新失败或磁盘空间不足时，当前安装版本仍可用。
- 回滚后 Agent 仍能按原生目录规则发现 Skill。
- 删除操作支持恢复，目录短暂不可访问不会触发云端批量删除。

## 16. 关键设计决策总结

| 决策 | 最终选择 |
| --- | --- |
| Skill 格式 | 优先兼容 Agent 原生 Skill 目录，平台元数据独立管理。 |
| 运行方式 | Skill 默认本地执行，云端只负责管理和分发。 |
| 同步模式 | 中心化管理、客户端拉取、本地缓存；授权目录支持双向同步。 |
| 隐私 | 本地同步默认个人私有，不自动公开或发布到团队。 |
| Git 更新 | 保留来源和 commit；默认检查后确认，安全且无冲突时才允许自动更新。 |
| 版本策略 | 发布制品不可变；项目锁文件固定版本和摘要；支持回滚。 |
| 安全 | 扫描、摘要、签名、权限和审计组合使用，不宣称绝对安全。 |
| 扩展 | MCP 作为独立远程工具层，后续接入，不与 Skill 注册中心耦合。 |
