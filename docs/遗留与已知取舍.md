# 遗留与已知取舍

这份文档只记两件事：**当初缺的那些东西现在怎么做的**，和**已经决定不做的取舍**。

已完成的历史修复记录在 git log 里（2026-10-22 ~ 10-31 的七轮审计与后续功能提交），
不再单列文档——要查当时为什么那么改，去翻对应 commit 的 message 与 diff。

## 一、已经落地的做法

清单上欠着的都做完了，做法如下：

| 缺口 | 现在的做法 |
| --- | --- |
| 回收期到期清理没有定时任务 | `RecycleScheduler` 默认开着，到点清过期条目（`skillmesh.recycle.cleanup-enabled` 可关）。看回收站时顺手清理的那一步留着——它不贵，且调度关掉时兜底 |
| 三个排序键没有对应索引 | V6 迁移建了三个索引，状态列放开头：等值条件定位到一段区间，后面的排序键直接出顺序，游标比较才能当索引边界用。V11 用 `CREATE INDEX IF NOT EXISTS` 再补一遍——老库上 V6 被 repair 改写成「跑过了」而索引其实没建，V11 补上。V12 再补两条「等值条件 + 排序」都有的路径：归档列表（属主 + 状态）与按状态过滤的安装列表，V6 那三个索引对不上这两条 |
| 状态值曾是裸 `String` | 17 个枚举类，实体字段用 `@Enumerated(EnumType.STRING)`。枚举常量名就是数据库里存的值，所以数据库不用迁移、接口取值不变。角色词表后来也套了枚举（见下）。取值一律不区分大小写：查询参数（`EnumParams`）与请求体（Jackson）两边口径一致，同一个值换个入口不会一个认一个不认——这比改之前宽了，`status=ACTIVE` 以前查不到东西，现在查得到 |
| 没有 HTTPS | 代码侧把路铺好了：`apps/web/nginx-tls.conf`（443 + 证书路径）与部署文档的「上 HTTPS」一节，签发与续期另有脚本（见下）。反代必须覆盖 `X-Forwarded-For` 并清掉 `Forwarded` 头，否则来源 IP 能被客户端伪造 |
| 版本状态里的 `scanning` 不可达 | 这一档删掉了：V13 迁移改掉 `skill_versions` 的状态约束，枚举、接口词表与前端词表同步删。留着它就有一个永远不出现的取值——客户端照它写分支，服务端永远不回它 | 设计文档 §10.1 |
| 集合的可见性建好后改不了 | 改集合与建集合拆成两个请求体（`UpdateGroupRequest` 只带可改的字段，slug 不在其中），`PATCH /api/v1/groups/{id}` 的 `visibility` 现在生效。权限规则：属主才能改；往组织/团队上挂要有那个范围的 `GROUP_PUBLISH`（与建集合同一道闸），收回来（改成 private/public）属主直接可以，可见范围只会变小。归属跟着可见性走——private/public 不挂组织，organization 要组织，team 还要该组织下的团队。换命名空间时先看目标空间里有没有同名 slug（排除它自己）。CLI 那边补了 `skillmesh group update` |
| 角色词表不套枚举 | 现在套了：真相在 `Role` 枚举里，常量名就是数据库里存的值、也是接口里传的值（`owner`/`admin`/`publisher`/`reviewer`/`member`/`viewer`），实体字段用 `@Enumerated(EnumType.STRING)`，所以数据库不用迁移、接口取值不变。等级顺序、可用范围、正则与 SQL 片段全从它派生（`Roles`），加一档角色只改枚举一处，不会出现「映射里没有、词表里有」的静默失效。团队与邀请能授的档位是它的子集（没有 owner 那一档）。词表与数据库 CHECK 约束在 `StatusVocabularyTest` 里对着看，加档位忘了改约束就红 |
| 审计表不归档、不分区 | 现在按月分区：V14 迁移把 `audit_events` 改成按 `occurred_at` 做 RANGE 分区，保留期过了整月分区直接 `DROP`——一条语句的事，删完空间也还回去，不用一行行 `DELETE`。保留多少个月由 `skillmesh.audit.retention-months` 定（默认 12），`AuditPartitionScheduler` 负责补本月与下月的分区、丢过期分区、清默认分区。默认分区是兜底：没覆盖到的月份先落那儿——审计写不进去比写得慢糟得多。分区表的主键带分区键（`id` + `occurred_at`），`id` 仍是 identity 列，游标照旧用「时间 + 数字 id」 |
| 符号链接不进同步模型 | 现在进了：链接指向的内容按内容算进包里（云端拿到的就是普通文件，不是链接），打包与算摘要走同一套遍历，两边的文件集始终一致。跟链接有三道闸：指向包根之外的跳过并报一声——包外的东西不该跟着上传，指向 `~/.ssh` 的链接会把私钥传上云；断链跳过，不让整次发布失败；成环的链接按「这个真实目录已经走过」收场，不重复展开。本机合并时仍然保留链接本身（写它指向的真实目录） |
| `license` 不自动判定 | 改成「自动识别，不自动判定」：服务端从制品里找许可证文件（`LICENSE` / `COPYING` 那一类），按正文特征认出 SPDX 标识填进来源行（`license_status=detected`），客户端给过表达式就不动。Git 导入那条路以前直接写 `detected` 却是空的，现在真的去 checkout 里认一份。能不能再分发仍然要人判断——`approved` / `restricted` / `incompatible` 那几档留给审核的人 |
| TLS 证书的签发与续期不归代码管 | 签发、续期、查有效期都有脚本了：`infra/scripts/tls-cert.sh issue|renew|check`（certbot 的 webroot 模式），续完自动 reload nginx——不 reload 的话新证书不生效。域名解析、CA 账号与证书挂载仍然是运维的事 |

## 二、明确不做的

这些是有意为之，不是欠账。想做的话先推翻这里的理由。

| 取舍 | 理由 | 出处 |
| --- | --- | --- |
| 迁移版本号只往后排 | 旧链用过 V1~V10，`e39692f` 把它们删光换成新链并复用了 V1~V5。当前链用到 V6、V11~V14，新加迁移从 V15 往后排——V7~V10 旧链也用过，在按旧链建过表的库上撞上去就是 checksum mismatch。`infra/scripts/check-migrations.sh` 现在会挡住插队与撞号 | 部署文档「改 schema 的三种方式」 |
