# 遗留与已知取舍

这份文档只记两件事：**代码里确实还缺的东西**，和**已经决定不做的取舍**。

已完成的历史修复记录在 git log 里（2026-10-22 ~ 10-30 的七轮审计与后续功能提交），
不再单列文档——要查当时为什么那么改，去翻对应 commit 的 message 与 diff。

## 一、仍然没做的

四条都是复核过、确认还存在的缺口。每条写清了现状与落点。

### 1. 回收期到期清理没有定时任务

`skill_recycle_files` 的过期条目只在**看回收站的时候**顺带清
（`RecycleService.list` 里先 `files.deleteExpired(now)` 再查）。

调度框架其实已经有了——`BackupScheduler` 用 `@Scheduled`，
`BackupScheduleConfig` 上的 `@EnableScheduling` 也已经在应用里，
只是它挂在 `skillmesh.backup.schedule-enabled` 开关上、没开时不启用调度。
所以再加一个回收站清理任务的成本是**几行**。

不改也不影响正确性：过期条目在查询时按 `expires_at` 过滤掉，读不到也恢复不了。

**落点**：`RecycleService` 旁边加一个 `@Scheduled` 方法，
或复用 `BackupScheduleConfig` 那套开关模式（默认不开）。

### 2. 三个排序键没有对应索引

数据量上来后这三处会退化成全表扫 + 排序：

| 查询 | 排序键 | 位置 |
| --- | --- | --- |
| 技能列表 / 搜索 | `(updated_at DESC, id DESC)` | `SkillRepository.search` |
| 待审队列 | `(submitted_at DESC NULLS LAST, created_at DESC, id DESC)` | `SkillVersionRepository.findReviewable` |
| 安装列表 | `last_updated_at DESC` | `InstallationRepository.findByUserIdOrderByLastUpdatedAtDesc` |

现有索引只覆盖了带前缀的部分：`idx_skills_owner_user (owner_user_id, updated_at DESC)`
能服务「我的 Skill」那一条路径，但全局列表（不限 owner）用不上它。

**落点**：新增一条迁移（V6），建这三个索引。索引要写入时维护，
所以等真的慢了再加——现在加是提前优化。

### 3. 状态值仍是裸 `String`

16 个实体字段用 `String` 存状态与可见性（`SkillEntity.status`/`visibility`、
`SkillVersionEntity.status`、`InstallationEntity.status`、`SyncChangesetEntity.status` 等）。

数据库的 CHECK 约束兜住了——代码里所有字面量都在 CHECK 列表内，写错会在建表时被拒。
但拼错的字符串不会编译报错，只会在运行期变成「一个没人认识的状态」。

改成枚举要动 15 个实体、20 多处调用点与原生 SQL 参数（`SkillStatus.ACTIVE_SQL`
这类常量就是绕开这个问题的临时办法），适合单独一轮。

**落点**：单独一轮机械改造，先从 `SkillVersionEntity.status` 起——它的取值最多。

### 4. 没有 HTTPS

compose 里 API 直连 `127.0.0.1:8080` 明文，`apps/web/nginx.conf` 只 `listen 80`。
设计文档 §14 要求 HTTPS。

这不该由代码单方面决定：证书要运维配合（域名、签发、续期、挂载），
反向代理放前面还是让应用自己终止 TLS 也是部署选择。

**落点**：部署侧的事。代码侧不需要改——nginx 加 `listen 443 ssl` 即可。

## 二、明确不做的

这些是有意为之，不是欠账。想做的话先推翻这里的理由。

| 取舍 | 理由 | 出处 |
| --- | --- | --- |
| 审计表不归档、不分区 | 首期数据量不值得引入分区；保留策略写在文档里 | 详细设计 §67 |
| `scanning` 状态不可达 | 扫描在转正的同一个事务里同步做完，没有可观察的中间态。要它可达得把扫描异步化（引入任务与状态轮询），不值当 | 设计文档 §10.1 |
| 符号链接不进同步模型 | 打包（`packager.Pack`）与算摘要（`skillscan.DirHashes`）都跳过符号链接，内容从不同步到云端。合并时保留符号链接，但不上传 | 设计文档 §6.1 |
| `license` 不自动判定 | 许可证识别只是线索，「能不能再分发」要人判断 | — |
