# 遗留与已知取舍

这份文档只记两件事：**当初缺的那些东西现在怎么做的**，和**已经决定不做的取舍**。

已完成的历史修复记录在 git log 里（2026-10-22 ~ 10-31 的七轮审计与后续功能提交），
不再单列文档——要查当时为什么那么改，去翻对应 commit 的 message 与 diff。

## 一、已经落地的做法

清单上欠着的都做完了，做法如下：

| 缺口 | 现在的做法 |
| --- | --- |
| 回收期到期清理没有定时任务 | `RecycleScheduler` 默认开着，到点清过期条目（`skillmesh.recycle.cleanup-enabled` 可关）。看回收站时顺手清理的那一步留着——它不贵，且调度关掉时兜底 |
| 三个排序键没有对应索引 | V6 迁移建了三个索引，状态列放开头：等值条件定位到一段区间，后面的排序键直接出顺序，游标比较才能当索引边界用。V11 用 `CREATE INDEX IF NOT EXISTS` 再补一遍——老库上 V6 被 repair 改写成「跑过了」而索引其实没建，V11 补上。V12 再补两条「等值条件 + 排序」都有的路径：归档列表（属主 + 状态）与按状态过滤的安装列表，V6 那三个索引对不上这两条 |
| 状态值曾是裸 `String` | 17 个枚举类，实体字段用 `@Enumerated(EnumType.STRING)`。枚举常量名就是数据库里存的值，所以数据库不用迁移、接口取值不变。角色词表没动（见下）。取值一律不区分大小写：查询参数（`EnumParams`）与请求体（Jackson）两边口径一致，同一个值换个入口不会一个认一个不认——这比改之前宽了，`status=ACTIVE` 以前查不到东西，现在查得到 |
| 没有 HTTPS | 代码侧把路铺好了：`apps/web/nginx-tls.conf`（443 + 证书路径）与部署文档的「上 HTTPS」一节。签证书、续期、挂载是运维的事。反代必须覆盖 `X-Forwarded-For` 并清掉 `Forwarded` 头，否则来源 IP 能被客户端伪造 |
| 集合的可见性建好后改不了 | 改集合与建集合拆成两个请求体（`UpdateGroupRequest` 只带可改的字段，slug 不在其中），`PATCH /api/v1/groups/{id}` 的 `visibility` 现在生效。权限规则：属主才能改；往组织/团队上挂要有那个范围的 `GROUP_PUBLISH`（与建集合同一道闸），收回来（改成 private/public）属主直接可以，可见范围只会变小。归属跟着可见性走——private/public 不挂组织，organization 要组织，team 还要该组织下的团队。换命名空间时先看目标空间里有没有同名 slug（排除它自己）。CLI 那边补了 `skillmesh group update` |

## 二、明确不做的

这些是有意为之，不是欠账。想做的话先推翻这里的理由。

| 取舍 | 理由 | 出处 |
| --- | --- | --- |
| 审计表不归档、不分区 | 首期数据量不值得引入分区；保留策略写在文档里 | 详细设计 §67 |
| `scanning` 状态不可达 | 扫描在转正的同一个事务里同步做完，没有可观察的中间态。要它可达得把扫描异步化（引入任务与状态轮询），不值当 | 设计文档 §10.1 |
| 符号链接不进同步模型 | 打包（`packager.Pack`）与算摘要（`skillscan.DirHashes`）都跳过符号链接，内容从不同步到云端。合并时保留符号链接，但不上传 | 设计文档 §6.1 |
| `license` 不自动判定 | 许可证识别只是线索，「能不能再分发」要人判断 | — |
| 角色词表不套枚举 | 组织/团队/成员的角色另有一套集中管理的词表与等级顺序（`Roles` / `RolePermissions`），字面量只出现在那一处。再套一层枚举只是多一份要同步的东西 | — |
| TLS 证书的签发与续期不归代码管 | 域名、签发、续期、挂载都得有运维配合。代码侧只提供配好路径的 nginx 配置与操作步骤 | 设计文档 §14 |
| 迁移版本号只往后排 | 旧链用过 V1~V10，`e39692f` 把它们删光换成新链并复用了 V1~V5。当前链用到 V6、V11 与 V12，新加迁移从 V13 往后排——V7~V10 旧链也用过，在按旧链建过表的库上撞上去就是 checksum mismatch | 部署文档「改 schema 的三种方式」 |
