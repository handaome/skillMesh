# 团队控制台使用手册

> 面向第二个人加入团队之后的日常操作：登录、邀请、发布到团队、审核、安装。

控制台是浏览器里的页面，发布与安装走 CLI。
起环境见 [README](../README.md#快速开始)，CLI 全部命令见 [CLI 使用手册](cli-使用手册.md)，概念与角色见 [团队治理与安全](团队治理.md)。

## 1. 登录

浏览器打开控制台首页（`http://127.0.0.1:5174`）。没登录会被带到登录页，点「登录」跳到 Keycloak 完成认证后回到控制台。

- 令牌存在浏览器 localStorage 里，有效期一年（Keycloak realm 的 `accessTokenLifespan: 31536000`）；期间由 `ensureFresh()` 静默续期，过期了会自动跳登录页。
- 登出在右上角。

## 2. 建组织与团队

组织是顶层空间，团队是组织下面的一组人。Skill 的可见性有四档：

| 可见性 | 谁能看 |
| --- | --- |
| private | 只有属主 |
| team | 该团队的成员，或该组织的 owner/admin |
| organization | 该组织的成员 |
| public | 所有人 |

建组织和建团队目前用 API（CLI 还没有这两个命令）：

```bash
TOKEN=$(curl -s -X POST "http://127.0.0.1:8180/kc/realms/skillmesh/protocol/openid-connect/token" \
  -d "grant_type=password" -d "client_id=skillmesh-test" \
  -d "username=dev-user" -d "password=dev" \
  | python -c "import sys,json;print(json.load(sys.stdin)['access_token'])")
ORG=$(curl -s -X POST http://127.0.0.1:8080/api/v1/organizations \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"slug":"acme","name":"Acme"}' | python -c "import sys,json;print(json.load(sys.stdin)['id'])")
curl -s -X POST "http://127.0.0.1:8080/api/v1/organizations/$ORG/teams" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"slug":"platform","name":"Platform"}'
```

这段用 `python` 解析 JSON。机器上没有 `python`，就把两处 `python -c` 换成 `jq -r .access_token` 和 `jq -r .id`。

建组织的人自动是 owner；建团队、发邀请都要 owner 或 admin。

团队页的成员表改的是**哪一层的角色**，取决于「范围」选的是整个组织还是某个团队：**选了团队**改的是这个团队里的**团队角色**（团队没有 owner 这一档），**选整个组织**改的是**组织角色**（多一档 owner）。页面会在成员表上方写明当前改的是哪一层、这一层管什么事。两层角色各管各的事——发布权看组织角色，审核放行权看团队角色，见 [团队治理](团队治理.md)。

## 3. 邀请成员

团队页 → 「邀请」区 → 选组织角色与团队角色 → 点「生成邀请链接」。

- 只有组织的 owner / admin 能发邀请。
- 链接 7 天内有效，库里只存哈希，明文只显示一次。
- 把链接发给对方；对方打开后登录并点「接受邀请」即入组。
- 发出后还能在列表里撤销。

## 4. 管理自己的 Skill

侧栏「我的 Skill」页列出你名下的全部 Skill——个人私有空间里的备份，以及你建的团队 Skill。选中一条，右侧是它的详情：

| 能做什么 | 怎么做 | 限制 |
| --- | --- | --- |
| 改名称、描述、标签 | 右侧「元数据」区改完点「保存」 | **slug 与可见性改不了**——会影响别人已经装的内容 |
| 看版本 | 右侧「版本」区 | 只看得到已发布的版本列表与摘要，每个版本带创建与发布时间 |
| 浏览内部文件 | 版本行右侧「浏览文件」 | 见下一节 |
| 撤回版本 | 版本行右侧「撤回」 | 撤回不可逆，恢复得发新版本；只有属主能撤 |
| 新建 Skill 元数据 | 右上角「新建 Skill」 | 只建元数据，**内容仍由 CLI 发布**；可见性限 private / public |
| 删除 Skill | 列表行右侧「删除」 | **软删除**：云端数据留着，可以还原；但各端同步后本地那份也会被删掉 |
| 还原删掉的 Skill | 页面底部「已删除」区点「还原」 | 只列出你自己删掉的那些 |

删除是软删除：云端的数据留着，slug 让出来（同名能重建），可以从页面底部的「已删除」区还原回去。
但各端同步后本地那份也会被删掉——本地这一步撤不回来，所以删除前有二次确认。

团队与组织可见的 Skill 由 `skillmesh publish --org/--team` 建立（见下一节），所以网页端的新建只支持个人空间。

### 按标签筛选

市场页与「我的 Skill」页的筛选行里有标签药丸，每个药丸后面带数量。
点一个就按这个标签筛，多选是「同时满足」；末尾还有一个「未打标」，
点它只看还没打标签的。

标签清单是单独取的一份，不是从当前这一页汇总的——列表是游标分页的，
从一页数据里汇总出来的只是这一页出现过的标签，想按一个只出现在第二页的标签
筛选时就没有那个选项可点了。清单的口径与搜索一致：只统计你看得见的那些
（可见范围 + 未归档），「我的 Skill」页只统计你名下的。

标签与「未打标」互斥：既是某个标签又没打标，说不通，所以选中哪个先动哪个。

### 批量操作

「我的 Skill」页每行左边有勾选框，勾上之后页面上方出现工具条：

- **批量打标签**——把选中的 Skill 的标签**统一覆盖**成对话框里那组。初值是它们的标签并集，
  改之前看得见最后会变成什么样。覆盖而不是「加标签」：加标签在多人协作里说不清该给谁加。
- **批量删除**——二次确认。这是软删除：云端数据留着，可以还原；但各端同步后本地那份
  也会被删掉。
- 结果分两栏报：**过了几条、没过几条**，没过的每条带原因。
- 逐条独立：一条没权限不影响其他条目，权限也与单条操作同一套（改标签只有属主能改，
  删除是属主或团队/组织的 publisher 及以上）。批量只是省了逐个点开详情页。
- 「取消选择」清空勾选。筛选条件变了，被筛掉的条目会自动退出勾选——
  选中的东西不在眼前时按批量操作，处理的对象就和以为的不一样了。

### 技能集合

侧栏「集合」页列出我可见的集合，每个集合一张卡片：名称、slug、成员与我装了几个。

- 成员逐个列出，装了的标「已装」，没装的标「未装」——一眼看出还差哪几个。
- **徽标只算「我装了几个」**：本人可见的数据。团队级的覆盖率（谁在哪台机器上
  装了多少）是另一种可见性，单独授权，不在这里混进来。
- 建集合与改成员走 CLI（`skillmesh group create` / `group install`）——
  跟发布走 CLI 是同一个道理：集合要落到具体的 Agent 目录上，那是本机的事。
- 卡片底部给出装齐的命令：`skillmesh group install <slug>`。

### 命令面板

按 `⌘K`（Windows 是 `Ctrl+K`）打开，一处搜 Skill 或跳页面：

- 搜 Skill 复用市场页的检索（`GET /skills?q=`），结果取前 8 条。
- 页面动作是静态的：市场、我的 Skill、团队、审核、审计。
- 上下键移动，回车执行，Esc 关闭。
- 跨实体检索（审计事件、审核条目、成员）没做——那要先给那几个端点补 `q`，是独立的后端需求。

## 5. 浏览与编辑 Skill 的内部文件

版本行点「浏览文件」，左边是文件树，右边是内容。

- 清单里的路径、大小、摘要都是**服务端从真的 zip 算出来的**，不是发布方自填的那份——自填的只是他的说法。
- 二进制文件（图片、字体等）不显示内容，只报大小。
- 单个文件超过 1 MB 也不显示内容。
- 能看见这个 Skill 才能看它的文件——文件内容不比元数据更该藏。
- 市场页的 Skill 详情里同样能浏览。

文本文件点「编辑」可以直接改，改完点「保存为新版本」。抽屉右上角「新建文件」可以加文件，文件标题栏的「删除」可以删文件。

**上传文件**：抽屉右上角「上传文件」从本机挑一个文件放进包里——图片、字体这类二进制走这条路（内容编码成 base64 传给服务端，文本框装不下）。路径默认取文件名，可以改；路径已存在会被覆盖。

**版本不可变**：保存不改原来那个版本，而是产出**新版本**——服务端基于源版本重打包，走一遍和 CLI 发布完全一样的流程（服务端扫描 → 个人与公开直接发布，团队与组织进待审核队列）。所以：

- 版本号默认在最大版本号上加一个 patch（1.0.0 → 1.0.1）。
- 团队可见的 Skill 编辑后停在待审核，要有人在审核页放行。
- 改动含密钥会被服务端扫描拦下，那一版直接作废。
- 编辑权限与发版一致：私有/公开只有属主能改，团队与组织要 publisher 及以上。
- 脚本的**可执行位**跟着文件一起带过去：编辑时勾「可执行」可以改它。没改权限位的文件保持原样。
- 二进制文件不能编辑——文本编辑框改不了图片；要用就删了重新上传。
- 单个文件上限 1 MB（base64 上传约 1.4 MB 请求体）。更大的文件走 CLI 发版，那条路直传对象存储。

## 6. 发布到团队

先用 `skillmesh login` 登录 CLI（见 [CLI 使用手册](cli-使用手册.md)），再发布：

```bash
skillmesh publish ./skills/java-debug --org acme --team platform
```

- `--org` / `--team` 传的是 **slug**，不是 id。
- 给了 `--team` 时可见性是 team，只给 `--org` 时是 organization。
- 发布权看的是**组织角色**：你在组织里要 publisher 及以上才能发。受邀入组默认是 member——要发到团队，让管理员在团队页**不选团队**时把你的组织角色提到 publisher。
- 团队与组织可见的版本**不会直接发布**，会停在待审核状态。

## 7. 审核

「审核」页列出待审版本。点进去能看到：

- 扫描结论与服务端扫描命中的规则
- 来源（仓库、分支、commit）
- 与上一个已发布版本的文件级差异（新增/修改/删除 + 增删行数）
- SKILL.md 正文

待审队列里每条也带提交时间，看得出哪个版本先提交、卡了多久。

差异大到只报文件级时，页面会明说「差异较大，只报文件级」。

reviewer 及以上角色才能看到并处理自己范围内的待审版本——这里看的是**团队角色**（团队里没有你的成员行时才回落到组织角色）。发布权则看**组织角色**，两层别混：见 [团队治理](团队治理.md)。

### 批量放行

待审数没有上限，逐条点开详情页是放不完的。列表每行左边有勾选框，勾上之后
页面上方出现工具条：

- **批量放行** / **批量拒绝**——放行要二次确认：放行即发布，团队成员就能装上这一版。
- 结果分两栏报：**过了几条、没过几条**，没过的每条带原因（哪一条、为什么）。
  逐条独立，一条没过不影响其他条目。
- 权限不放宽：批量里的每一条都照样走单条审核的那几道闸——reviewer 角色、
  不能审自己发布的版本、扫描结论阻断。批量只是省了逐条点开详情页。
- 「取消选择」清空勾选。换了筛选条件后，被筛掉的条目会自动退出勾选——
  选中的东西不在眼前时按批量放行，放行的对象就和以为的不一样了。

## 8. 安装

审核通过后，团队成员就能装：

```bash
skillmesh search java-debug
skillmesh install <skill-id>
```

`search` 输出的最后一列是 Skill 的完整 ID，把它喂给 `install`。

团队可见的 Skill，该团队的成员与该组织的 owner/admin 能搜到并下载。

## 9. 审计流水

控制台的「审计」页按时间倒序列出流水：谁、什么时候、对哪个 Skill 做了什么、结果如何。

| 动作 | 含义 |
| --- | --- |
| 创建 Skill / 改 Skill 元数据 | 改了哪些字段写在 details 里 |
| 发布版本 / 提交审核 / 审核放行 / 审核拒绝 / 撤回版本 | 发版这条线上的每一步 |
| 删除 Skill / 还原 Skill | 软删除：数据留着，随时能还原 |
| 同步上传 / 同步拉取 / 本地随云端删除 | 后两类由客户端上报（服务端看不见本地那一侧） |
| 登记安装 / 更新安装记录 / 注销安装 | 装在哪儿、还装不装 |
| 下载制品 | 谁拉走了哪一版 |

展开某条能看 details：改了哪些字段、哪个版本、冲突原因。

本机另有一份日志（`skillmesh logs`），记的是这台机器上的细节——服务端看不来的那些事，比如云端删除传到本地后删的是哪个目录。

## 10. 排错

| 现象 | 原因 |
| --- | --- |
| 登录页报「登录状态校验失败」 | state 对不上，重新点一次登录 |
| 邀请页显示已失效 | 超过 7 天或已被撤销，重新生成 |
| 看不到待审版本 | 你在这个范围的**团队角色**不到 reviewer 及以上——你在该团队里有成员行时看那行，没有则回落到组织角色。改哪一层：控制台里**选中该团队**改的是团队角色，**不选团队**改的是组织角色（见 [团队治理](团队治理.md)） |
| CLI 报「组织 xxx 不存在或你不是成员」 | `--org` 传的是 slug；用 `skillmesh` 登录的账号不在这个组织里 |
| CLI 报「你在组织 "xxx" 的角色是 member，发布到组织/团队需要 publisher 及以上」 | 发布权看的是**组织角色**——让组织管理员把你的**组织角色**提到 publisher（控制台里不选团队时改的就是组织角色） |

## 11. 浏览器端到端验收

```bash
cd apps/web && pnpm e2e
```

要 **API、前端 dev server、Keycloak 都在本机跑着**（缺哪个脚本会直接说清楚）。
脚本用系统自带的 Edge/Chrome 驱动真实浏览器，走完这条闭环：

1. A 登录 Web（Keycloak 授权码 + PKCE），顶栏显示用户；
2. 市场页没有手贴 token 的输入框；
3. 团队页列出组织成员；
4. 改组织角色（publisher → member → publisher）生效；
5. 选中团队后列标题从「组织角色」变成「团队角色」；
6. 生成邀请链接；
7. B 打开链接，未登录时提示「登录后接受」；
8. B 登录后接受邀请，页面显示「已加入」；
9. A 在审核队列看到待审版本，进详情有 SKILL.md 正文与文件级差异；
10. 点「通过」后版本状态变 published；
11. 负例：B（非 reviewer）打开审核队列是空的；
12. 负例：唯一 owner 改自己的角色，页面报错。

**不引 Playwright**：它要额外下载浏览器二进制（本机网络受限），而开发机本来就有 Edge/Chrome——
CDP 是它们都有的调试协议，`apps/web/e2e/lib/cdp.mjs` 用 node 内置的 WebSocket 直连，
**不新增任何依赖**。上传用的 zip 也是手搓的（`e2e/lib/zip.mjs`，store 模式）。

账号、组织、团队可以用环境变量换：
`SKILLMESH_E2E_USER_A` / `_PASS_A` / `_USER_B` / `_PASS_B` / `_ORG` / `_TEAM` / `_SLUG` / `_WEB` / `_API` / `_ISSUER`。
浏览器位置不对时用 `SKILLMESH_E2E_BROWSER` 指到可执行文件。

**它会改动数据**：改 `dev-user2` 的组织角色（跑完改回 publisher）、生成一份邀请、
发一个测试 Skill（固定 slug `e2e-v2-console`，每次跑新增一个版本）。测试 Skill 可以到
「我的 Skill」页点「删除」清掉——那是软删除，云端留着记录，可以从「已删除」区还原。
