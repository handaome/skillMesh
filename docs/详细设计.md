# SkillMesh 数据库 SQL、OpenAPI 接口规范与 CLI 命令详细设计

> 文档版本：V1.0  
> 日期：2026-10-19  
> 产品名称：SkillMesh  
> 文档类型：研发接口与数据设计基线  
> 适用范围：后端、CLI/Daemon、Web 前端、测试、运维与安全评审

本文在《SkillMesh：Agent Skill 协作与分发平台最终设计文档》的基础上，将核心设计落实为可用于项目初始化和接口联调的数据库 DDL、OpenAPI 3.1 契约和 CLI 行为规范。示例域名、OIDC Issuer、对象存储地址及部分策略参数是部署占位值，上线时由环境配置提供。

## 0. 设计约束与约定

### 0.1 必须遵守的规则

1. **Skill 内容与安装实例分离**：Skill 的云端逻辑实体、每个不可变版本、Git 来源、本地安装实例分别建模。
2. **发布版本不可变**：已发布版本的内容、摘要、制品地址不可原位更换；有修改必须创建新版本。
3. **本地同步默认私有**：本地目录同步至个人空间不等同于团队发布；团队共享需要单独授权或审核。
4. **来源可追溯**：Git 安装记录仓库、子目录、ref、实际解析 commit 和内容摘要；不把凭据写入 URL、日志或 Skill 文件。
5. **安全后安装**：下载先进入临时目录，完成路径校验、大小限制、摘要验证和策略扫描后，才替换 Agent 目录中的当前版本。
6. **冲突不静默覆盖**：双向同步以共同基线比较；同一文件两端都变化时，优先三方合并，无法合并则保留冲突副本并暂停该 Skill 的自动覆盖。
7. **API 授权由服务端决定**：客户端传入的组织 ID、团队 ID、Skill ID 均不代表授权。每次读取、下载、发布、审批都必须服务端鉴权。
8. **凭据不进入制品**：Git 凭据引用只指向本机凭据管理器或服务端受控 Secret 引用；不得将长期令牌写入数据库普通字段。

### 0.2 命名规范

- API 前缀：`/api/v1`。
- JSON 字段：`snake_case`。
- 数据库表与字段：`snake_case`；主键使用 UUID。
- 时间字段统一使用 `timestamptz`，存储 UTC。
- 版本摘要使用 SHA-256 十六进制小写字符串。
- 标识符 ID 与展示用 `slug` 分离。`slug` 不作为安全授权凭据。
- API 错误统一返回 `application/problem+json` 风格的 JSON 错误对象。
- 列表接口统一支持 `limit`、`cursor`；不使用会因插入而漂移的深分页 offset 作为主要分页方式。

# 第一部分：PostgreSQL 数据库设计

## 1.1 数据库选型和迁移约束

- 数据库：PostgreSQL 15 或更高版本。
- UUID 默认使用 PostgreSQL `gen_random_uuid()`；需要 `pgcrypto` 扩展。
- DDL 通过 Flyway 或 Liquibase 管理，生产环境禁止人工直接修改表结构。
- 应用数据库账号不应拥有 `SUPERUSER`；扩展由数据库管理员预先安装。
- 审计数据按保留策略归档；正式环境可以按时间分区，但首期不强制分区。
- 对象存储中的 Skill 制品与数据库事务无法形成传统分布式事务，上传采用“先写临时对象、校验成功、数据库提交、异步清理孤儿对象”的流程。

## 1.2 完整初始化 DDL

以下 SQL 是首期基线结构，适用于新建数据库。已有数据库需通过迁移脚本逐版升级，不应直接覆盖现有 schema。

```sql
BEGIN;

CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- ========== 用户与组织 ==========
CREATE TABLE users (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    oidc_issuer     text NOT NULL,
    oidc_subject    text NOT NULL,
    display_name    text NOT NULL,
    email           text,
    status          text NOT NULL DEFAULT 'active'
                    CHECK (status IN ('active', 'disabled', 'pending')),
    last_login_at   timestamptz,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now(),
    UNIQUE (oidc_issuer, oidc_subject)
);
CREATE INDEX idx_users_status ON users(status);

CREATE TABLE organizations (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    slug            text NOT NULL UNIQUE,
    name            text NOT NULL,
    status          text NOT NULL DEFAULT 'active'
                    CHECK (status IN ('active', 'suspended', 'archived')),
    policy_json     jsonb NOT NULL DEFAULT '{}'::jsonb,
    created_by      uuid REFERENCES users(id) ON DELETE SET NULL,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE organization_memberships (
    organization_id uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    user_id         uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role            text NOT NULL CHECK (role IN ('owner', 'admin', 'publisher', 'reviewer', 'member', 'viewer')),
    joined_at       timestamptz NOT NULL DEFAULT now(),
    created_by      uuid REFERENCES users(id) ON DELETE SET NULL,
    PRIMARY KEY (organization_id, user_id)
);
CREATE INDEX idx_org_memberships_user ON organization_memberships(user_id, organization_id);

CREATE TABLE teams (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    slug            text NOT NULL,
    name            text NOT NULL,
    description     text,
    status          text NOT NULL DEFAULT 'active'
                    CHECK (status IN ('active', 'archived')),
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now(),
    UNIQUE (organization_id, slug),
    UNIQUE (organization_id, id)
);

CREATE TABLE team_memberships (
    team_id         uuid NOT NULL REFERENCES teams(id) ON DELETE CASCADE,
    user_id         uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role            text NOT NULL CHECK (role IN ('admin', 'publisher', 'reviewer', 'member', 'viewer')),
    joined_at       timestamptz NOT NULL DEFAULT now(),
    added_by        uuid REFERENCES users(id) ON DELETE SET NULL,
    PRIMARY KEY (team_id, user_id)
);
CREATE INDEX idx_team_memberships_user ON team_memberships(user_id, team_id);

-- ========== Skill 主体与来源 ==========
CREATE TABLE skills (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    slug            text NOT NULL,
    name            text NOT NULL,
    description     text NOT NULL DEFAULT '',
    owner_user_id   uuid REFERENCES users(id) ON DELETE SET NULL,
    organization_id uuid REFERENCES organizations(id) ON DELETE RESTRICT,
    owner_team_id   uuid,
    visibility      text NOT NULL DEFAULT 'private'
                    CHECK (visibility IN ('private', 'team', 'organization', 'public')),
    status          text NOT NULL DEFAULT 'active'
                    CHECK (status IN ('active', 'archived', 'quarantined')),
    tags            text[] NOT NULL DEFAULT '{}',
    metadata_json   jsonb NOT NULL DEFAULT '{}'::jsonb,
    latest_version  text,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now(),
    archived_at     timestamptz,
    CHECK (owner_user_id IS NOT NULL OR organization_id IS NOT NULL),
    CHECK (visibility <> 'team' OR (owner_team_id IS NOT NULL AND organization_id IS NOT NULL)),
    FOREIGN KEY (organization_id, owner_team_id)
        REFERENCES teams(organization_id, id) DEFERRABLE INITIALLY IMMEDIATE
);
CREATE UNIQUE INDEX uq_skills_personal_slug
    ON skills(owner_user_id, slug) WHERE organization_id IS NULL AND owner_user_id IS NOT NULL;
CREATE UNIQUE INDEX uq_skills_org_slug
    ON skills(organization_id, slug) WHERE organization_id IS NOT NULL;
CREATE INDEX idx_skills_visibility_status ON skills(visibility, status);
CREATE INDEX idx_skills_owner_user ON skills(owner_user_id, updated_at DESC);
CREATE INDEX idx_skills_org_team ON skills(organization_id, owner_team_id);
CREATE INDEX idx_skills_tags ON skills USING gin(tags);
CREATE INDEX idx_skills_metadata ON skills USING gin(metadata_json);

CREATE TABLE skill_sources (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    skill_id            uuid NOT NULL REFERENCES skills(id) ON DELETE CASCADE,
    source_type         text NOT NULL CHECK (source_type IN ('local_import', 'git', 'registry', 'archive')),
    provider            text CHECK (provider IN ('github', 'gitlab', 'gitee', 'generic_git', 'local', 'skillmesh')),
    repository_url      text,
    subpath             text,
    ref_type            text CHECK (ref_type IN ('branch', 'tag', 'commit', 'default', 'local')),
    ref_value           text,
    resolved_commit     text,
    license_expression  text,
    license_status      text NOT NULL DEFAULT 'unknown'
                        CHECK (license_status IN ('unknown', 'detected', 'approved', 'restricted', 'incompatible')),
    credential_ref      text, -- 只保存受控 Secret/本机凭据引用，不保存凭据本体
    source_fingerprint  text,
    created_by          uuid REFERENCES users(id) ON DELETE SET NULL,
    created_at          timestamptz NOT NULL DEFAULT now(),
    updated_at          timestamptz NOT NULL DEFAULT now(),
    CHECK ((source_type = 'git' AND repository_url IS NOT NULL) OR source_type <> 'git'),
    CHECK (repository_url IS NULL OR repository_url !~* '://[^/]*:[^/@]+@'),
    CHECK (subpath IS NULL OR (subpath !~ '(^/|(^|/)\.\.(/|$))'))
);
CREATE INDEX idx_skill_sources_skill ON skill_sources(skill_id, created_at DESC);
CREATE INDEX idx_skill_sources_repo ON skill_sources(repository_url) WHERE repository_url IS NOT NULL;

-- ========== 制品、版本与扫描 ==========
CREATE TABLE artifacts (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    sha256          char(64) NOT NULL UNIQUE,
    storage_key     text NOT NULL UNIQUE,
    content_type    text NOT NULL DEFAULT 'application/zip',
    size_bytes      bigint NOT NULL CHECK (size_bytes >= 0),
    file_count      integer NOT NULL CHECK (file_count >= 0),
    manifest_json   jsonb NOT NULL DEFAULT '[]'::jsonb,
    signature       text,
    signature_key_id text,
    created_at      timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE skill_versions (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    skill_id            uuid NOT NULL REFERENCES skills(id) ON DELETE RESTRICT,
    source_id           uuid REFERENCES skill_sources(id) ON DELETE SET NULL,
    version             text NOT NULL,
    channel             text NOT NULL DEFAULT 'stable'
                        CHECK (channel IN ('stable', 'beta', 'dev')),
    source_commit       text,
    artifact_id         uuid REFERENCES artifacts(id) ON DELETE RESTRICT,
    changelog           text NOT NULL DEFAULT '',
    manifest_json       jsonb NOT NULL DEFAULT '{}'::jsonb,
    status              text NOT NULL DEFAULT 'draft'
                        CHECK (status IN ('draft', 'scanning', 'pending_review', 'published', 'rejected', 'revoked', 'yanked')),
    created_by          uuid REFERENCES users(id) ON DELETE SET NULL,
    published_by        uuid REFERENCES users(id) ON DELETE SET NULL,
    created_at          timestamptz NOT NULL DEFAULT now(),
    published_at        timestamptz,
    revoked_at          timestamptz,
    revoke_reason       text,
    UNIQUE (skill_id, version),
    CHECK ((status <> 'published') OR published_at IS NOT NULL),
    CHECK ((status <> 'revoked') OR revoked_at IS NOT NULL),
    CHECK ((status NOT IN ('published', 'revoked', 'yanked')) OR artifact_id IS NOT NULL)
);
CREATE INDEX idx_skill_versions_skill_created ON skill_versions(skill_id, created_at DESC);
CREATE INDEX idx_skill_versions_status ON skill_versions(status, published_at DESC);
CREATE INDEX idx_skill_versions_artifact ON skill_versions(artifact_id);

ALTER TABLE skills
    ADD CONSTRAINT fk_skills_latest_version
    FOREIGN KEY (id, latest_version) REFERENCES skill_versions(skill_id, version)
    DEFERRABLE INITIALLY DEFERRED;

CREATE TABLE skill_scans (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    skill_version_id    uuid NOT NULL REFERENCES skill_versions(id) ON DELETE CASCADE,
    scanner_name        text NOT NULL,
    scanner_version     text NOT NULL,
    status              text NOT NULL CHECK (status IN ('passed', 'warning', 'failed', 'error')),
    findings_json       jsonb NOT NULL DEFAULT '[]'::jsonb,
    summary             text NOT NULL DEFAULT '',
    started_at          timestamptz NOT NULL DEFAULT now(),
    completed_at        timestamptz,
    CHECK (completed_at IS NULL OR completed_at >= started_at)
);
CREATE INDEX idx_skill_scans_version ON skill_scans(skill_version_id, started_at DESC);

CREATE TABLE skill_reviews (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    skill_version_id    uuid NOT NULL REFERENCES skill_versions(id) ON DELETE CASCADE,
    reviewer_id         uuid NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    decision            text NOT NULL CHECK (decision IN ('approved', 'rejected', 'changes_requested')),
    comment             text NOT NULL DEFAULT '',
    created_at          timestamptz NOT NULL DEFAULT now(),
    UNIQUE (skill_version_id, reviewer_id)
);
CREATE INDEX idx_skill_reviews_version ON skill_reviews(skill_version_id, created_at DESC);

-- ========== 权限 ==========
CREATE TABLE skill_permissions (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    skill_id        uuid NOT NULL REFERENCES skills(id) ON DELETE CASCADE,
    subject_type    text NOT NULL CHECK (subject_type IN ('user', 'team', 'organization')),
    subject_id      uuid NOT NULL,
    permission      text NOT NULL CHECK (permission IN ('view', 'install', 'publish', 'review', 'admin')),
    granted_by      uuid REFERENCES users(id) ON DELETE SET NULL,
    created_at      timestamptz NOT NULL DEFAULT now(),
    UNIQUE (skill_id, subject_type, subject_id, permission)
);
CREATE INDEX idx_skill_permissions_subject ON skill_permissions(subject_type, subject_id, skill_id);

-- ========== 设备、安装与同步 ==========
CREATE TABLE devices (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    device_key      text NOT NULL,
    display_name    text NOT NULL DEFAULT '',
    platform        text NOT NULL DEFAULT 'unknown',
    cli_version     text NOT NULL DEFAULT '',
    last_seen_at    timestamptz,
    revoked_at      timestamptz,
    created_at      timestamptz NOT NULL DEFAULT now(),
    UNIQUE (user_id, device_key)
);
CREATE INDEX idx_devices_user ON devices(user_id, last_seen_at DESC);

CREATE TABLE installations (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id             uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    device_id           uuid REFERENCES devices(id) ON DELETE SET NULL,
    skill_id            uuid NOT NULL REFERENCES skills(id) ON DELETE RESTRICT,
    skill_version_id    uuid REFERENCES skill_versions(id) ON DELETE SET NULL,
    source_id           uuid REFERENCES skill_sources(id) ON DELETE SET NULL,
    agent               text NOT NULL CHECK (agent IN ('claude-code', 'codex', 'cursor', 'generic')),
    install_scope       text NOT NULL CHECK (install_scope IN ('user', 'project', 'custom')),
    project_root        text,
    target_path         text NOT NULL,
    installed_version   text,
    installed_commit    text,
    installed_sha256    char(64),
    update_policy       text NOT NULL DEFAULT 'notify'
                        CHECK (update_policy IN ('manual', 'notify', 'auto_safe')),
    local_modified      boolean NOT NULL DEFAULT false,
    status              text NOT NULL DEFAULT 'active'
                        CHECK (status IN ('active', 'missing', 'conflict', 'uninstalled', 'blocked')),
    installed_at        timestamptz NOT NULL DEFAULT now(),
    last_checked_at     timestamptz,
    last_updated_at     timestamptz,
    UNIQUE (user_id, device_id, target_path, skill_id)
);
CREATE INDEX idx_installations_user ON installations(user_id, status);
CREATE INDEX idx_installations_skill ON installations(skill_id, status);
CREATE INDEX idx_installations_device ON installations(device_id, last_checked_at DESC);

CREATE TABLE sync_states (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    device_id           uuid NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
    skill_id            uuid NOT NULL REFERENCES skills(id) ON DELETE CASCADE,
    local_path          text NOT NULL,
    local_revision      text,
    cloud_revision      text,
    base_revision       text,
    local_manifest_hash char(64),
    cloud_manifest_hash char(64),
    status              text NOT NULL DEFAULT 'in_sync'
                        CHECK (status IN ('in_sync', 'local_ahead', 'cloud_ahead', 'conflict', 'paused', 'error')),
    last_synced_at      timestamptz,
    last_error_code     text,
    last_error_message  text,
    updated_at          timestamptz NOT NULL DEFAULT now(),
    UNIQUE (device_id, skill_id, local_path)
);
CREATE INDEX idx_sync_states_device_status ON sync_states(device_id, status);
CREATE INDEX idx_sync_states_skill ON sync_states(skill_id, updated_at DESC);

CREATE TABLE sync_changesets (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    device_id           uuid NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
    skill_id            uuid NOT NULL REFERENCES skills(id) ON DELETE CASCADE,
    idempotency_key     text NOT NULL,
    direction           text NOT NULL CHECK (direction IN ('upload', 'download', 'bidirectional')),
    base_revision       text,
    target_revision     text,
    status              text NOT NULL DEFAULT 'queued'
                        CHECK (status IN ('queued', 'processing', 'completed', 'conflict', 'rejected', 'failed', 'cancelled')),
    manifest_json       jsonb NOT NULL DEFAULT '[]'::jsonb,
    summary_json        jsonb NOT NULL DEFAULT '{}'::jsonb,
    error_code          text,
    error_message       text,
    created_at          timestamptz NOT NULL DEFAULT now(),
    started_at          timestamptz,
    completed_at        timestamptz,
    UNIQUE (device_id, idempotency_key),
    CHECK (completed_at IS NULL OR started_at IS NULL OR completed_at >= started_at)
);
CREATE INDEX idx_sync_changesets_device ON sync_changesets(device_id, created_at DESC);
CREATE INDEX idx_sync_changesets_status ON sync_changesets(status, created_at);

CREATE TABLE sync_conflicts (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    changeset_id        uuid NOT NULL REFERENCES sync_changesets(id) ON DELETE CASCADE,
    relative_path       text NOT NULL,
    base_sha256         char(64),
    local_sha256        char(64),
    cloud_sha256        char(64),
    conflict_type       text NOT NULL CHECK (conflict_type IN ('both_modified', 'delete_modify', 'path_collision', 'binary_conflict', 'unknown')),
    status              text NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'resolved_local', 'resolved_cloud', 'resolved_merged', 'dismissed')),
    resolution_json     jsonb NOT NULL DEFAULT '{}'::jsonb,
    created_at          timestamptz NOT NULL DEFAULT now(),
    resolved_at         timestamptz,
    UNIQUE (changeset_id, relative_path)
);
CREATE INDEX idx_sync_conflicts_status ON sync_conflicts(status, created_at);

-- ========== 上传会话 ==========
-- 临时上传对象在校验通过后，才能被提升为不可变制品或同步文件对象。
CREATE TABLE upload_sessions (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    actor_user_id       uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    device_id           uuid REFERENCES devices(id) ON DELETE SET NULL,
    purpose             text NOT NULL CHECK (purpose IN ('skill_artifact', 'sync_file')),
    skill_version_id    uuid REFERENCES skill_versions(id) ON DELETE CASCADE,
    changeset_id        uuid REFERENCES sync_changesets(id) ON DELETE CASCADE,
    relative_path       text,
    expected_sha256     char(64),
    expected_size_bytes bigint NOT NULL CHECK (expected_size_bytes >= 0),
    temporary_storage_key text NOT NULL UNIQUE,
    status              text NOT NULL DEFAULT 'created'
                        CHECK (status IN ('created', 'uploaded', 'verifying', 'completed', 'failed', 'expired')),
    expires_at          timestamptz NOT NULL,
    uploaded_at         timestamptz,
    verified_at         timestamptz,
    error_code          text,
    created_at          timestamptz NOT NULL DEFAULT now(),
    CHECK (
      (purpose = 'skill_artifact' AND skill_version_id IS NOT NULL AND changeset_id IS NULL AND relative_path IS NULL)
      OR
      (purpose = 'sync_file' AND skill_version_id IS NULL AND changeset_id IS NOT NULL AND relative_path IS NOT NULL)
    ),
    CHECK (expected_sha256 IS NULL OR expected_sha256 ~ '^[a-f0-9]{64}$')
);
CREATE INDEX idx_upload_sessions_actor ON upload_sessions(actor_user_id, created_at DESC);
CREATE INDEX idx_upload_sessions_status_expiry ON upload_sessions(status, expires_at);
CREATE UNIQUE INDEX uq_sync_upload_path
    ON upload_sessions(changeset_id, relative_path)
    WHERE purpose = 'sync_file';

CREATE TABLE audit_events (

    outcome         text NOT NULL CHECK (outcome IN ('success', 'denied', 'failure')),

);
CREATE INDEX idx_audit_events_time ON audit_events(occurred_at DESC);
CREATE INDEX idx_audit_events_actor_time ON audit_events(actor_user_id, occurred_at DESC);
CREATE INDEX idx_audit_events_target ON audit_events(target_type, target_id, occurred_at DESC);
CREATE INDEX idx_audit_events_action_time ON audit_events(action, occurred_at DESC);

-- 常用自动更新时间由应用层统一维护；也可用数据库触发器实现。
COMMIT;
```

### 1.3 DDL 落地说明

1. `skills.latest_version` 是查询优化字段，必须由发布事务统一更新；不能允许客户端直接指定任意值。发布事务应验证对应 `skill_versions.status = 'published'`。
2. SQL 层无法仅靠普通 `CHECK` 约束实现跨表的“发布后不可修改”规则。服务层必须禁止修改已发布版本的 `artifact_id`、`version`、`source_commit`、`manifest_json`；生产环境可增加数据库触发器作为纵深防护。
3. `skill_permissions.subject_id` 需按 `subject_type` 在服务层校验指向有效的用户、团队或组织。若项目要求数据库级强一致，可以拆成三张 ACL 表，避免多态外键。
4. `repository_url` 的简单约束只用于阻止常见带账号密码 URL，并不能替代 URL 规范化和 SSRF 防护。服务层仍需禁止危险协议、回环/链路本地地址和不允许的重定向。
5. `skills` 的唯一索引允许个人空间与组织空间使用同名 `slug`。服务层应统一 slug 规则，例如小写字母、数字、连字符，长度 2–64。
6. `installations` 的 `target_path` 是本机路径信息，仅用户本人及必要的平台诊断功能可访问，不应暴露给团队市场公开查询。
7. 私有云端草稿可以使用 `skills.visibility='private'` 和 `skill_versions.status='draft'` 表示；正式团队发布必须走审核状态机。

### 1.4 发布事务建议

正式发布必须在一个数据库事务中执行下列逻辑：

1. 锁定对应 `skills` 行，防止并发发布同一个版本。
2. 确认版本处于 `pending_review`，扫描策略通过且审核权限满足要求。
3. 确认 `artifact_id` 所对应制品已上传、哈希校验完成、清单合法。
4. 将版本状态变更为 `published`，填充 `published_by`、`published_at`。
5. 更新 `skills.latest_version`，写入 `audit_events`。
6. 提交事务后发送通知事件；通知失败不能回滚已完成的发布，应通过事件/outbox 机制重试。

### 1.5 建议补充的不可变版本触发器（可选）

下面是纵深防护示例。若使用该触发器，状态字段可更新为 `revoked`/`yanked`，但核心制品字段不可改。

```sql
CREATE OR REPLACE FUNCTION prevent_published_skill_version_mutation()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
    IF OLD.status IN ('published', 'revoked', 'yanked') THEN
        IF NEW.skill_id IS DISTINCT FROM OLD.skill_id
           OR NEW.version IS DISTINCT FROM OLD.version
           OR NEW.artifact_id IS DISTINCT FROM OLD.artifact_id
           OR NEW.source_commit IS DISTINCT FROM OLD.source_commit
           OR NEW.manifest_json IS DISTINCT FROM OLD.manifest_json THEN
            RAISE EXCEPTION 'published skill version content is immutable';
        END IF;
    END IF;
    RETURN NEW;
END;
$$;

CREATE TRIGGER trg_skill_version_immutable
BEFORE UPDATE ON skill_versions
FOR EACH ROW EXECUTE FUNCTION prevent_published_skill_version_mutation();
```

# 第二部分：OpenAPI 3.1 接口规范

## 2.1 通用约定

### Base URL

- 本地开发：`http://localhost:8080/api/v1`
- 生产示例：`https://skills.example.com/api/v1`

### 身份认证

使用 OIDC/OAuth 2.0 Bearer Access Token。API 本身不接受用户提交的 `user_id` 作为身份依据。服务端通过 token 的 issuer/subject 映射用户。CLI 的登录流程优先采用 Device Authorization Grant 或浏览器 PKCE 流程；不要求用户把密码输入 CLI。

### 标准响应规则

- 成功读取：返回资源 JSON 或列表包装结构。
- 创建资源：`201 Created`，响应包含资源 ID 和 `Location`（适用时）。
- 异步扫描、发布、同步：`202 Accepted`，返回任务 ID/资源状态。
- 有并发版本控制的更新：要求 `If-Match` 或明确的 `expected_revision`。
- 可重试写请求：支持 `Idempotency-Key`。
- 限流响应：`429 Too Many Requests`，提供 `Retry-After`。
- 无权限或资源不可见时，私有资源可按安全策略统一返回 `404`，避免泄露资源存在性。

### 错误响应结构

```json
{
  "type": "https://skills.example.com/problems/version-conflict",
  "title": "Version conflict",
  "status": 409,
  "code": "VERSION_CONFLICT",
  "detail": "The remote revision changed after the client read it.",
  "request_id": "req_01J...",
  "retryable": false,
  "field_errors": []
}
```

客户端应根据 `code` 分支处理，不应解析 `detail` 文本来判定业务状态。

## 2.4 上传和下载协议补充

大制品建议采用预签名 URL 或受控上传会话，API 服务不必代理所有文件字节。建议流程：

1. CLI 先提交 `POST /skills/{id}/versions`，传入预期摘要、字节数和文件清单。
2. 服务端校验调用者权限、容量配额和版本号唯一性后，返回短时有效的上传 URL。
3. CLI 上传压缩包到临时对象键。预签名 URL 有效期建议 5–15 分钟，并限制方法、对象键及内容长度。
4. 服务端异步校验归档路径、文件数、解压后总大小、`SKILL.md`、文件摘要和恶意内容。
5. 校验通过后将制品提升为不可变对象并登记 `artifacts`；校验失败则标记候选版本失败并清理临时对象。
6. 下载前再次鉴权。下载 URL 只用于短时访问；撤销权限后不得继续签发新 URL。

不要直接信任客户端提交的 manifest。服务端必须重新计算归档内实际路径和哈希，并与上传声明比对。

### 2.4.1 版本制品上传完整流程

1. `POST /skills/{skill_id}/versions` 创建 `draft` 候选版本，版本记录的 `artifact_id` 暂为空，返回 `upload_session_id`/上传 URL。
2. CLI 使用短时 URL 上传归档字节，不把对象存储凭据写入配置文件。
3. CLI 调用 `POST /uploads/{upload_id}/complete`。服务端验证字节数、SHA-256、压缩包路径与文件清单。
4. 校验通过后服务端创建 `artifacts` 记录，关联到版本记录，将状态推进到 `scanning`；随后由扫描流程推进 `pending_review` 或 `rejected`。
5. 上传 URL 过期时，客户端重新申请上传会话；不得复用已失效或已完成的上传会话。

### 2.4.2 同步文件上传完整流程

1. `POST /sync/changesets` 创建待处理 changeset 并绑定 `device_id`、`skill_id`、`base_revision`。
2. 对 `upsert` 文件调用 `POST /sync/changesets/{id}/uploads`，服务端为每个相对路径创建短时上传会话。
3. 客户端逐个上传文件并调用 `POST /uploads/{upload_id}/complete` 完成校验。
4. 客户端调用 `POST /sync/changesets/{id}/commit`，传入期望的云端 revision。
5. 服务端若发现云端 revision 已变化，返回冲突并保留双方版本；否则生成新 revision、提交 manifest 并返回同步摘要。
6. `delete` 操作只提交相对路径和基线信息；若基线不一致或目标文件已更新，则转入冲突，不直接删除。

## 2.5 权限矩阵建议

| 操作 | 个人所有者 | 团队 Member | Publisher | Reviewer | Org Admin |
|---|---:|---:|---:|---:|---:|
| 查看私有个人 Skill | 是 | 否 | 否 | 否 | 默认否，除非组织策略授权 |
| 安装团队可见 Skill | 按所有者权限 | 是 | 是 | 是 | 是 |
| 创建候选版本 | 是 | 否/按团队策略 | 是 | 默认否 | 是 |
| 审核版本 | 否/按职责分离 | 否 | 默认否 | 是 | 按策略 |
| 发布团队版本 | 个人空间不适用 | 否 | 是 | 默认否 | 是 |
| 撤回版本 | 个人版本可管理 | 否 | 按策略 | 否 | 是/安全管理员 |
| 查看组织审计 | 否 | 否 | 否 | 按授权 | 是 |

权限服务应同时评估用户角色、资源可见性、Skill ACL 和组织策略。发布人与审核人是否必须不同，应由组织安全策略决定；安全敏感仓库建议强制双人审批。

# 第三部分：CLI 命令详细设计

## 3.1 CLI 目标与运行模式

二进制命名：`skillmesh`。命令在 Windows、macOS、Linux 上保持一致；Linux/macOS 可运行前台 Daemon，桌面系统可注册为系统用户服务。CLI 默认不需要管理员权限。

- CLI 负责一次性操作和交互：登录、搜索、添加来源、安装、检查更新、发布、回滚。
- Daemon 负责常驻操作：目录监听、自动同步、离线队列、定期检查更新。
- Agent 继续直接读取原生 Skill 目录，不依赖 CLI 在线运行。

### 3.1.1 配置路径

| 操作系统 | 配置与状态目录建议 |
|---|---|
| Linux | `${XDG_CONFIG_HOME:-~/.config}/skillmesh`；缓存使用 `${XDG_CACHE_HOME:-~/.cache}/skillmesh` |
| macOS | `~/Library/Application Support/SkillMesh`；缓存放 `~/Library/Caches/SkillMesh` |
| Windows | `%APPDATA%\\SkillMesh`；缓存放 `%LOCALAPPDATA%\\SkillMesh\\Cache` |

配置目录与缓存目录分开；凭据优先交给系统 Keychain/Credential Manager/libsecret 保存。配置文件只保存非敏感设置和凭据引用。

### 3.1.2 配置文件示例

`~/.config/skillmesh/config.yaml`：

```yaml
server: https://skills.example.com
profile: default
network:
  timeout_seconds: 30
  max_retries: 5
sync:
  enabled: true
  default_new_skill_policy: ask # ask | private | local_only
  default_update_policy: notify # manual | notify | auto_safe
  debounce_ms: 1200
  delete_protection_days: 30
  max_file_size_mb: 20
  max_total_size_mb: 50
security:
  block_detected_secrets: true
  reject_symlinks_outside_root: true
  allowed_git_protocols: [https, ssh]
agents:
  claude-code:
    enabled: true
    user_skills_dir: ~/.claude/skills
  codex:
    enabled: true
    user_skills_dir: ~/.codex/skills
  cursor:
    enabled: false
    user_skills_dir: ~/.cursor/skills
```

路径只是默认值，可通过 `skillmesh agents detect` 检测实际环境，并由适配器按 Agent 当前版本验证。不要把上述配置目录视为所有 Agent 版本永久不变的硬编码事实。

## 3.2 全局参数

| 参数 | 说明 |
|---|---|
| `--server URL` | 覆盖服务端地址。 |
| `--profile NAME` | 使用指定配置档。 |
| `--project PATH` | 指定项目根目录；默认从当前目录向上查找 `.git` 或 `skillmesh.yaml`。 |
| `--agent NAME` | 目标 Agent：`claude-code`、`codex`、`cursor`、`generic`、`all`。 |
| `--scope user|project|custom` | 安装范围。 |
| `--json` | 输出稳定 JSON，供脚本调用。 |
| `--quiet` | 减少普通提示，但错误仍输出到 stderr。 |
| `--verbose` | 输出诊断日志；敏感字段始终脱敏。 |
| `--no-color` | 禁用 ANSI 色彩。 |
| `--yes` | 对可安全自动确认的提示采用默认值；不得绕过安全阻断、权限或破坏性覆盖。 |
| `--dry-run` | 只显示计划，不写入本地文件、不提交云端状态。 |
| `--timeout DURATION` | 命令整体超时，例如 `30s`、`2m`。 |

退出码：

| 退出码 | 含义 |
|---:|---|
| `0` | 成功，无需额外处理。 |
| `1` | 未分类错误。 |
| `2` | 参数或配置错误。 |
| `3` | 未登录/认证失败。 |
| `4` | 权限不足。 |
| `5` | 网络或服务端不可用，可按 `retryable` 判断是否重试。 |
| `6` | 安全策略阻断。 |
| `7` | 检测到冲突，需要人工处理。 |
| `8` | 目标 Agent 或目录未检测到/不可写。 |
| `9` | 目标资源不存在。 |

机器可读模式应输出 JSON 到 stdout；日志和交互提示写入 stderr。不能在 stdout 混入进度条或 ANSI 控制字符。

## 3.3 登录与身份

### `skillmesh login`

用法：

```bash
skillmesh login
skillmesh login --server https://skills.example.com
skillmesh login --server https://skills.example.com --device-code
skillmesh login status
skillmesh logout
```

行为：

1. 打开系统浏览器，使用 OIDC 授权流程；无浏览器环境时显示 Device Authorization URL 和一次性 code。
2. CLI 获取短期访问令牌及刷新令牌，令牌存入系统凭据库。
3. 使用 `/me` 验证令牌并展示当前账号、组织和角色。
4. `logout` 撤销服务端会话（若支持），清理本地凭据引用；不删除本地 Skill。

安全规则：不提供 `login --password`；不建议把 Bearer Token 放在命令行参数中，避免进入 Shell 历史与进程列表。

## 3.4 Skill 搜索与查看

### `skillmesh search`

```bash
skillmesh search "java service debug"
skillmesh search --tag java --source git --visibility public
skillmesh search "release" --limit 50 --json
```

参数：`--tag`、`--source`、`--visibility`、`--org`、`--team`、`--limit`、`--cursor`、`--json`。

行为：只返回调用者有权查看的资源；默认先展示名称、简述、作者/组织、最新稳定版本、来源、许可证状态、扫描状态。无权访问的私有资源不能通过错误信息或搜索总数泄露存在性。

### `skillmesh info`

```bash
skillmesh info java-service-debug
skillmesh info 0d4a5f1a-0000-4000-8000-000000000000 --versions
skillmesh info java-service-debug --version 1.2.0 --json
```

展示详情、版本历史、制品摘要、Git 来源/ref/commit、许可证检测结果、扫描摘要、权限与撤回状态。对已撤回版本显示明确警告；不能将已撤回版本列为默认安装版本。

## 3.5 Git 来源解析、添加与安装

### `skillmesh source resolve`

```bash
skillmesh source resolve https://github.com/owner/agent-skills
skillmesh source resolve https://git.example.com/team/skills.git --path skills/java-debug --ref v1.2.0
```

行为：解析规范化仓库 URL、ref 实际 commit，并扫描候选 Skill 目录；仅列出符合目录规范的候选项。私有仓库必须使用凭据管理器中的凭据引用。服务器侧解析和本地直接 clone 模式由部署策略决定；无论在哪执行，都必须做路径与资源限制校验。

### `skillmesh add`

用途：登记一个来源；不保证自动安装，建议 `--install` 才写入 Agent 目录。

```bash
skillmesh add https://github.com/owner/agent-skills
skillmesh add https://github.com/owner/agent-skills --path skills/java-debug
skillmesh add https://github.com/owner/agent-skills --path skills/java-debug --ref v1.2.0 --install
skillmesh add git@git.example.com:team/skills.git --path skills/release --ref main --credential-ref corp-git
```

参数：

- `--path PATH`：仓库子目录。仓库只有一个候选 Skill 时可省略；多个候选 Skill 时必须选择或交互确认。
- `--ref REF`：可与 `--ref-type branch|tag|commit|default` 搭配；默认使用仓库默认分支。
- `--agent NAME`：目标 Agent；`all` 只安装到已启用且检测通过的适配器。
- `--scope user|project|custom`：默认 `project`（若检测到项目根目录），否则提示用户。
- `--install`：解析和扫描通过后立即安装。
- `--update-policy manual|notify|auto-safe`：默认 `notify`。
- `--credential-ref REF`：本机凭据管理器中的凭据引用，不接受明文 token。
- `--name NAME`：本地覆盖显示名，仅作别名，不改变上游 Skill 元数据。

输出必须包括规范化仓库 URL、子目录、解析 commit、安装路径、摘要与扫描结论。风险扫描失败时默认阻断安装；仅有低风险 warning 时可根据策略要求显式确认。

### `skillmesh install`

```bash
skillmesh install java-service-debug --agent claude-code --scope project
skillmesh install https://github.com/owner/repo --path skills/db-migration --agent codex
skillmesh install java-service-debug --version 1.2.0 --agent all --dry-run
```

支持来源类型：

- SkillMesh 云端 Skill ID/slug。
- 已登记的本地来源名。
- Git URL + 可选子路径与 ref。

安装事务：

1. 解析 Skill 来源并确认版本/commit。
2. 下载到缓存临时目录。
3. 校验压缩包和文件路径，拒绝路径穿越、目录外符号链接、超大文件与禁用文件。
4. 校验文件清单/摘要并执行本地安全扫描。
5. 生成安装计划并检测目标目录的同名 Skill。
6. 同名未受 SkillMesh 管理时，默认不覆盖；可用 `--replace` 进入交互式备份/冲突流程。
7. 复制到临时目标目录，原子切换至最终目标路径；记录来源、版本与摘要。
8. 注册安装实例；注册服务暂不可用时标记为待上报，不撤销已经校验成功的本地安装。

## 3.6 本地 Skill 扫描与无感同步

### `skillmesh scan`

```bash
skillmesh scan
skillmesh scan ~/.claude/skills --agent claude-code
skillmesh scan --all-agents --json
skillmesh scan --include-unmanaged --dry-run
```

默认扫描配置中已启用的 Skill 根目录。输出新发现、已管理、内容变化、路径冲突、被忽略、疑似敏感文件等分类。不应扫描整个用户目录，也不应将无法访问目录当作空目录并据此同步删除。

### `skillmesh sync`

```bash
skillmesh sync
skillmesh sync --skill java-service-debug
skillmesh sync --direction upload --skill java-service-debug
skillmesh sync --direction download --skill team-release-checklist
skillmesh sync --all --dry-run
skillmesh sync --resolve keep-local --conflict <conflict-id>
```

参数：

- `--direction upload|download|both`：同步方向，默认 `both`。
- `--skill ID_OR_NAME`：指定一个 Skill。
- `--all`：处理所有已授权同步项。
- `--resolve keep-local|keep-cloud|keep-merged|keep-both`：解决指定冲突；`keep-merged` 需要本地合并文件并重算摘要。
- `--conflict ID`：指定待解决冲突。
- `--force`：只允许在交互确认并有可回滚快照的情况下用于覆盖；不能绕过安全扫描和权限校验。

同步机制：

1. 本地文件事件触发防抖扫描，而不是直接上传单个 watcher 事件。
2. 计算规范化文件 manifest；过滤 `.git`、缓存、临时文件和敏感路径。
3. 与 `base_revision`、本地 manifest、云端 manifest 比较，形成 changeset。
4. 使用 `Idempotency-Key` 提交 changeset；重复重试不得重复创建云端版本。
5. 云端返回冲突时不自动覆盖，写入本地冲突状态和解决建议。
6. 上传失败进入持久队列；退避重试并在达到上限后给出可诊断错误。
7. 删除默认使用软删除/回收期；只有明确配置并确认后才传播删除。

### `skillmesh watch`

```bash
skillmesh watch start
skillmesh watch status
skillmesh watch pause
skillmesh watch resume
skillmesh watch stop
```

在前台可由 `skillmesh daemon run` 托管；生产桌面/开发机环境建议注册为用户级服务。`watch pause` 只暂停后台同步，不影响 Agent 读取现有 Skill 文件。Daemon 启动时做全量 reconcile，以弥补文件系统通知丢失。

### `skillmesh daemon`

```bash
skillmesh daemon run
skillmesh daemon install
skillmesh daemon uninstall
skillmesh daemon logs --tail 200
```

服务安装/卸载操作必须只更改用户级服务配置，不默认要求 root/管理员权限。若操作系统不支持服务注册，可保留前台运行模式。

## 3.7 检查更新、预览、更新与回滚

### `skillmesh update --check`

```bash
skillmesh update --check
skillmesh update --check --all
skillmesh update --check --skill java-service-debug --json
```

只查询远端 ref 与当前安装版本的差异，不改本地文件。输出 current/latest commit、版本、差异文件、风险变化、许可证状态、是否存在本地修改以及是否可自动升级。

### `skillmesh update`

```bash
skillmesh update java-service-debug
skillmesh update --all
skillmesh update java-service-debug --to 1.2.0
skillmesh update java-service-debug --to-commit 4d39a2f
skillmesh update --all --policy auto-safe --dry-run
```

规则：

- `--to VERSION` 与 `--to-commit SHA` 互斥。
- 固定到 commit/tag 的来源不会静默跟随分支；显式指定目标版本/commit 才升级。
- `manual` 策略不执行自动升级；`notify` 仅提示；`auto-safe` 只在无本地修改、扫描通过、签名/摘要验证通过且无新增高风险能力时执行。
- 更新前创建本地回滚点或确保可重新获取原版本。
- 目标目录有本地改动时停止自动更新，可生成 diff 或使用 `--save-local-changes` 创建本地补丁。
- 安装完成后重新计算摘要并注册新安装状态；失败时原子回退到旧版本。

### `skillmesh rollback`

```bash
skillmesh rollback java-service-debug --to 1.1.0
skillmesh rollback java-service-debug --previous
skillmesh rollback java-service-debug --dry-run
```

回滚只变更本机安装内容，不会将旧版本重新发布到云端，也不会更改 Git 上游。若目标版本已被安全撤回，应默认拒绝回滚；只有具备权限并显式使用经组织策略允许的安全例外时才可安装已撤回版本，且必须写本地与服务端审计事件。

## 3.8 发布与审核

### `skillmesh publish`

```bash
skillmesh publish ./skills/java-debug
skillmesh publish ./skills/java-debug --version 1.2.0 --channel stable
skillmesh publish ./skills/java-debug --visibility private --dry-run
skillmesh publish ./skills/java-debug --org engineering --team platform --submit-review
```

推荐流程：

1. 本地验证目录和 `SKILL.md` 元数据。
2. 生成临时归档和逐文件 manifest。
3. 执行本地敏感信息与危险操作扫描。
4. 通过 API 创建候选版本并上传制品。
5. 服务端重新解包计算摘要、执行扫描、检查来源与许可证规则。
6. `--submit-review` 将版本转入审核；个人私有草稿可按策略免团队审核，但依旧不能跳过安全检查。
7. 只有有发布权限的主体才能发布组织/团队版本。

`--visibility public` 只能用于用户明确授权公开的操作；需要交互提示确认，不能被 `--yes` 自动弱化。

## 3.10 项目级配置与锁文件

项目根目录可包含：

```text
project/
├── skillmesh.yaml
├── skillmesh.lock.yaml
└── .agents/skills/...
```

`skillmesh.yaml` 示例：

```yaml
version: 1
skills:
  - name: java-service-debug
    source:
      type: git
      repository: https://github.com/example/agent-skills.git
      path: skills/java-debug
      ref_type: tag
      ref: v1.2.0
    install:
      agents: [claude-code, codex]
      scope: project
    update_policy: notify
```

`skillmesh.lock.yaml` 示例：

```yaml
version: 1
resolved_at: "2026-10-19T10:00:00Z"
skills:
  - name: java-service-debug
    source_id: "<source-id>"
    repository: https://github.com/example/agent-skills.git
    path: skills/java-debug
    ref_type: tag
    ref: v1.2.0
    resolved_commit: "<full-commit-sha>"
    version: 1.2.0
    sha256: "<artifact-sha256>"
    agents: [claude-code, codex]
```

项目级安装按 lock 文件复现，除非用户执行 `skillmesh update` 或 `skillmesh lock refresh`。CI 环境建议执行 `skillmesh install --locked`：如果远端解析结果与 lock 文件不符则失败，防止构建环境静默漂移。

# 第四部分：安全、测试与开发验收

## 4.1 服务端必须校验的事项

- 身份、组织成员关系和对象级权限。
- Git URL 协议、主机、重定向目标和访问目标 IP；防止 SSRF、访问云元数据地址和回环网络。
- 压缩包路径穿越、符号链接、硬链接、大小、文件数、解压后总大小及压缩比。
- 制品摘要必须由服务端对实际字节重新计算。
- `SKILL.md` frontmatter 与目录格式校验；不信任客户端上报的扫描结果。
- 对象存储预签名 URL 时限、权限、对象键和写入方法范围。
- 审核、发布、撤回必须记录审计事件。
- 请求限流、文件上传限额、下载并发限制和 Git 获取超时。

## 4.2 CLI 必须校验的事项

- 本地路径规范化，安装/删除目标必须位于配置的 Agent 根目录或用户明确授权的自定义根目录内。
- 不跟随目录外部符号链接；不覆盖未由 SkillMesh 管理的同名目录，除非用户明确执行替换流程。
- 更新前检查本地差异并保存回滚点。
- Token 存储在系统凭据库；日志不包含敏感请求头或 URL 中的凭据。
- 同步使用幂等键；重试不重复应用删除或重复创建版本。
- 不将用户工作文件的绝对路径、文件内容和 Git 私有 URL 无限制发送到遥测系统。

## 4.3 自动化测试清单

| 编号 | 场景 | 预期结果 |
|---|---|---|
| DB-001 | 同一 Skill 创建重复版本号 | 唯一约束拒绝，API 返回 `VERSION_ALREADY_EXISTS`。 |
| DB-002 | 发布后修改制品 ID | 数据库触发器或服务层阻止。 |
| AUTH-001 | 未授权用户读取私有 Skill | 返回 404 或组织策略规定的拒绝响应，不泄露存在性。 |
| GIT-001 | Git 仓库包含多个 Skill 目录 | 返回候选清单，用户明确选择目标路径。 |
| GIT-002 | URL 指向回环/内网敏感地址 | 服务端阻断，写安全审计。 |
| INST-001 | 目标目录存在非 SkillMesh 管理的同名目录 | 默认拒绝覆盖并提供备份/冲突提示。 |
| UPD-001 | 上游 commit 变化且本地无改动 | 预览差异，按 update policy 决定是否更新。 |
| UPD-002 | 本地文件和远程同一文件均变化 | 不静默覆盖，建立冲突记录。 |
| SYNC-001 | 网络上传中断后重试 | 基于幂等键完成单次 changeset。 |
| SYNC-002 | 两设备同一文件并发修改 | 发现冲突，用户选择解决方式后继续。 |
| SEC-001 | Skill 包含已识别的密钥 | 上传/安装按策略阻断，不在日志输出密钥值。 |
| SEC-002 | 压缩包包含 `../..` 路径 | 解包阶段拒绝。 |
| RB-001 | 更新后的 Skill 无法完成安装 | 回滚至原始工作版本，状态明确。 |
| DEL-001 | 监控目录临时不可用 | 不向云端传播批量删除。 |
| API-001 | 带同一 Idempotency-Key 重试创建请求 | 返回同一操作结果，不创建重复资源。 |
| API-002 | If-Match 与当前 ETag 不符 | 返回 `412 PRECONDITION_FAILED`。 |

## 4.4 统一错误码

| 错误码 | HTTP | 可重试 | 处理建议 |
|---|---:|---|---|
| `AUTH_REQUIRED` | 401 | 否 | 重新登录。 |
| `TOKEN_EXPIRED` | 401 | 否 | 刷新凭据或重新登录。 |
| `PERMISSION_DENIED` | 403/404 | 否 | 检查组织角色和资源权限。 |
| `RESOURCE_NOT_FOUND` | 404 | 否 | 检查 ID/slug 及可见性。 |
| `VALIDATION_FAILED` | 422 | 否 | 根据 `field_errors` 修正参数。 |
| `VERSION_ALREADY_EXISTS` | 409 | 否 | 选择新版本号或查看已有版本。 |
| `VERSION_CONFLICT` | 409 | 取决于场景 | 重新读取资源并让用户确认。 |
| `PRECONDITION_FAILED` | 412 | 可重新读取后重试 | ETag/修订号过期。 |
| `SYNC_CONFLICT` | 409 | 否，需处理 | 使用冲突解决命令。 |
| `SOURCE_UNREACHABLE` | 502/504 | 是 | 检查网络、代理、Git 凭据后重试。 |
| `SOURCE_UNSUPPORTED` | 422 | 否 | 使用支持的 Git 协议/来源。 |
| `SECURITY_SCAN_FAILED` | 422 | 否 | 查看扫描项并修复，不能自动忽略阻断项。 |
| `ARTIFACT_HASH_MISMATCH` | 422 | 否 | 丢弃制品并重新打包/下载。 |
| `QUOTA_EXCEEDED` | 413/429 | 视情况 | 检查组织配额或文件体积。 |
| `RATE_LIMITED` | 429 | 是 | 按 `Retry-After` 重试。 |
| `INTERNAL_ERROR` | 500 | 通常是 | 提供 request_id 给管理员排查。 |

## 4.5 最小可交付范围（MVP）

MVP 应优先确保端到端工作闭环，而不是一次实现所有治理功能：

1. PostgreSQL DDL 与 Flyway migration。
2. OIDC 登录、`GET /me`、Skill 搜索/详情和版本查询。
3. Git 来源解析、候选 Skill 选择、安装至 Claude Code/Codex。
4. 本地安装记录与 `skillmesh list/status/doctor`。
5. 检查更新、差异预览、固定 commit 和回滚。
6. 私有云端备份、changeset 幂等、离线队列和基础冲突记录。
7. 敏感信息扫描、哈希验证、审计事件与最低限度的团队权限。

在本地同步和 Git 安装更新稳定后，再增加团队审批流、自动安全更新、更多 Agent 适配器和 MCP 工具集成。

# 附录 A：开发实现注意事项

1. **OpenAPI 是契约，不是自动生成的完整业务实现。** 后端应对本文件运行 OpenAPI lint；契约发生变化时同步更新客户端模型与契约测试。
2. **上传制品的临时态与正式态应分开。** 临时对象设置自动过期；正式对象按摘要寻址并禁止覆盖。
3. **同步 revision 不要直接等同于 Git commit。** 本地同步 revision 是 SkillMesh 的变更序号/摘要；Git commit 只表示上游仓库某一状态。
4. **不要通过覆盖原目录实现更新。** 使用 staging 目录、校验、原子替换和回滚点。
5. **不要把个人云端备份自动提升为可发现的市场版本。** 备份、草稿、已审核发布是不同状态。
6. **权限撤销后要停止新下载与同步。** 已下载到用户设备的文件无法被服务器保证瞬时远程擦除；客户端应在下一次联网时呈现撤回通知。
7. **第三方许可证必须保留出处和识别结果。** 自动识别结果不能替代法律判断；组织可配置不允许再分发的许可证策略。
8. **保持 Agent Adapter 可版本化。** 对每个 Agent 的目录、覆盖规则和 frontmatter 兼容性建立回归测试；不在业务服务中散落硬编码路径。
